# CareerLens Frontend

**최신 버전: `v2026.10.10-0227` · 2026-10-10 02:27 KST**

승인된 **눈 아이콘**을 공통 화면과 로그인·회원가입 화면의 헤더에 적용했습니다. Career Lens 로고명과 기존 크기·이동 동작은 유지합니다. 현재 작업본에서는 **마이페이지에서 로그인 계정에 자동 저장된 보고서를 다시 열 수 있습니다.** 위 버전은 기존 게시 버전이며, GitHub 업로드는 별도 요청이 있을 때만 진행합니다. Pull 전에 [전체 변경 기록](VERSION_HISTORY.md)을 확인하세요.

승인된 **포슬린 블루 · 스튜디오 보고서 · 사파이어 동공 로딩 · 클리어 사파이어 피라미드 · 블루 오빗 전환**을 팀 FastAPI 백엔드에 연결합니다. 페이지와 모션은 HTML/CSS·브라우저 ES module이며 화면 실행에 npm 설치나 빌드가 필요하지 않습니다.

진행표는 **이력서 → 채용공고 → 모의지원**입니다. 채용공고 안에서 희망 직무 선택 → 관련 공고 선택을 순서대로 진행하며, 공고를 먼저 선택하고 이력서를 첨부하는 경로도 지원합니다. **비회원도 로그인 전에 실제 분석·점수 계산을 완료합니다.** 프론트 Python 서버가 기존 백엔드 분석 엔진을 가져와 실행하고, 완성된 결과를 비공개 임시 저장소에 보관합니다. 로그인·회원가입 후에는 인증을 확인해 같은 결과를 계정에 연결하고 **재분석이나 두 번째 로딩 화면 없이 표시**합니다. 회원의 기존 FastAPI `/evaluations`·개인 보고서 API에는 계속 인증이 필요합니다. 프론트 `src/shared/api/backend-adapter.js`가 두 실행·저장 경로를 화면 계약에 맞춥니다.

## 실행

발표·테스트용 Render 배포 준비는 [Render 배포 안내](infra/deploy/render.md)를 참고하세요. 저장소 루트의 `render.yaml`은 **무료 프론트 웹서비스 1개·수동 배포**만 정의합니다. 현재 로컬 준비 상태이며 실제 서비스 생성이나 GitHub 업로드는 수행하지 않았습니다. 백엔드 없이 프론트만 배포하는 환경에는 공개 가상 공고 스냅샷을 함께 제공합니다.

프로젝트 상위 폴더의 `start.bat`은 Python 3.12+ 공유 환경에서 프론트 5300, FastAPI 5301, 별도 평가 워커를 실행합니다. `start.bat --no-worker --no-browser`는 대기 평가를 가져가지 않고 API·화면만 확인하는 모드입니다. 자세한 내용은 [상위 실행 안내](../README.md)를 참고하세요.

비회원 실제 분석에는 형제 `CareerLens-backend`의 분석 엔진·Python 의존성과 서버 측 모델 설정이 필요합니다. 프론트만 단독 배포하거나 엔진을 사용할 수 없으면 연결 오류를 표시하며 완료된 분석으로 가장하지 않습니다. `--no-worker`는 회원 평가 워커만 중지합니다. 비회원 분석 실행까지 막고 화면만 확인하려면 `CAREERLENS_GUEST_ANALYSIS=0`을 설정하세요. 상세 경계와 API는 [비회원 결과 연결 안내](docs/api/guest-report-handoff.md)를 참고하세요.

프론트만 따로 실행하려면 이 저장소에서 다음을 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

프론트 `.env`에는 API 서버 주소와 공개 프론트 설정만 넣습니다. `/api` 경로를 붙이지 않습니다.

```dotenv
BACKEND_URL=http://127.0.0.1:5301
FRONTEND_PORT=5300
```

```powershell
.\.venv\Scripts\python server.py
```

원격 API는 `https://api.example.com` 같은 HTTPS origin을 사용합니다. 원격 평문 HTTP는 지원하지 않습니다. 설정 우선순위는 `--backend-url` → 프로세스 환경변수 → `.env`입니다. 환경 파일은 단순한 `KEY=value`이며 셸 명령을 실행하지 않습니다. `/health`는 프론트 생존과 API 주소 설정 여부만 나타냅니다. API 연결 실패는 502, 주소 미설정은 503으로 표시합니다.

## 현재 API·인증 연결

회원 API의 현재 로컬 연결은 **브라우저 `http://127.0.0.1:5300/api/v1/...` → Python 프론트 프록시 → FastAPI `http://127.0.0.1:5301/api/v1/...`**입니다. 비회원 분석·결과 연결용 `/api/v1/local-guest/...`는 프론트 Python 서버가 직접 처리합니다. `api()`는 브라우저의 공통 요청 함수입니다. 내부 어댑터가 화면용 계약을 실제 API 요청으로 바꾸면 공통 요청 처리가 `/api/v1` 경로로 전송합니다. `BACKEND_URL=http://127.0.0.1:5301`은 프론트 서버가 접속할 API origin이므로 `/api/v1`을 덧붙여 설정하지 않습니다. 프록시는 요청 경로와 `Authorization`, `Idempotency-Key`, `Last-Event-ID`를 보존합니다. Supabase 프로젝트 URL 자체를 `BACKEND_URL`로 쓰지 않습니다.

`127.0.0.1`은 각 프로세스가 실행되는 PC 자신을 뜻합니다. 브라우저 주소에서는 브라우저를 실행한 PC, `BACKEND_URL`에서는 프론트 서버를 실행한 PC입니다. 이 주소는 팀원 PC나 공유 원격 서버의 주소가 아닙니다. 팀원은 각자의 로컬 서버를 실행하거나 실제로 접근 가능한 공유 API의 HTTPS origin을 설정해야 합니다.

실제 계정은 백엔드의 이메일·비밀번호 로그인/가입을 사용합니다. 백엔드에서 발급한 access/refresh token과 프론트 임시 작업 상태는 브라우저 `sessionStorage`에 보관합니다. 현재 백엔드에는 OAuth와 비밀번호 재설정 API가 없으므로 해당 기능을 실제 지원하는 것처럼 표시하지 않습니다. 명시적 합성 시연 모드는 실제 계정·평가와 구분합니다.

이메일 인증 후 현재 앱으로 돌아오는 Supabase 해시 콜백은 주소에서 즉시 제거합니다. 새 토큰은 백엔드 `/me` 검증에 성공한 뒤에만 저장하고 기존 로그인·임시 이력서 연결 흐름을 사용합니다. 실패한 콜백은 기존 세션을 덮어쓰지 않으며, 만료·사용된 링크는 로그인 및 담당자 문의를 안내합니다. 비밀번호 복구 콜백은 지원하지 않습니다. 프론트가 인증 메일 재발송이나 인증 우회를 수행하지 않습니다.

Supabase의 Site URL·허용 리디렉션은 실제 사용하는 브라우저 origin(로컬 기본값 `http://127.0.0.1:5300`)에 맞게 **프로젝트 관리자가** 설정해야 합니다. `localhost:3000` 등 다른 주소로 도착한 링크는 이 앱이 처리할 수 없으며 이미 만료된 링크를 복구하지도 못합니다. 첨부한 이력서는 탭별 임시 저장이므로 메일 인증 후 원래 작업하던 창으로 돌아와 로그인하세요.

로그인 전 입력·공고 선택·분석 상태는 브라우저 탭의 `sessionStorage`에 보관합니다. 실제 분석을 시작하면 프론트 서버의 `/local-guest/analyses`가 계산을 수행하며, 보고서 본문·점수는 인증 전 브라우저에 전달하지 않습니다. 임시 결과는 프론트 서버의 비공개 `.runtime/guest-reports.sqlite3`에 저장하고, 최대 30분 또는 최초 첨부의 남은 유효 기간 중 더 짧은 기간을 적용합니다. 파일 교체로 시간을 늘리지 않습니다. 서버는 만료된 미연결 결과를 정리하고 취소·폐기 요청도 처리합니다.

완료된 결과 화면에서 로그인·가입하면 `/local-guest/analyses/{id}/claim`이 백엔드 `/me`로 인증을 확인한 뒤 결과를 해당 계정에 연결합니다. 이미 계산한 결과를 바로 표시하며 이력서 재업로드나 새 평가 생성은 하지 않습니다. **인증 후 3초 이내 표시가 목표이며, 실제 인증·네트워크를 포함한 시간은 실측 전 보장하지 않습니다.** 이메일 확인이 필요한 가입은 인증이 끝난 뒤 결과를 연결합니다. 분석 전 준비만 한 상태에서 로그인하면 입력을 기존 회원 경로로 옮깁니다. 마이페이지·저장 보고서를 열기 위한 로그인은 임시 작업 연결을 건너뛰고 요청한 계정 화면으로 돌아옵니다.

연결한 비회원 보고서는 프론트 서버의 계정별 저장소에서 다시 조회·삭제할 수 있으며, 기존 FastAPI 보고서 DB로 자동 이관하지 않습니다. 이 저장소는 과거 `guest_workspaces` 계약과 별개입니다. 운영 배포에서는 프론트 저장소의 지속성을 별도로 준비해야 합니다. 저장 파일을 잃으면 계정에 연결된 결과도 복구되지 않습니다.

OpenAI 키, Supabase service role 키, DB URL·비밀번호는 **백엔드 `.env` 전용**입니다. 프론트 JavaScript, `public/`, 프론트 `.env`, 커밋에 넣지 마세요. 프론트 Python 비회원 엔진은 기존 서버 설정을 읽고 모델 키를 브라우저로 전달하지 않습니다. 회원 평가·이력서는 백엔드 환경설정의 Supabase, 비회원 분석에서 연결한 보고서는 프론트의 비공개 저장소를 사용합니다. 이전 자료를 자동 이전하지 않으며 `.runtime`·DB·개인 이력서·보고서는 Git 대상에서 제외합니다.

## 업로드·공고·평가

2026-10-12 실제 점수·평가 근거·공고 데이터 연결 수정과 미구현 API 구분은 [프론트–백엔드 연결 점검](docs/api/frontend-backend-audit-20261012.md)에 정리했습니다. 실제 회원의 공고 작성·수정·삭제·관심 저장은 백엔드 API 연동 전까지 비활성입니다.

- 첨부 화면은 **UTF-8 Markdown(.md), 최대 10MiB**만 받습니다. 브라우저가 업로드 전에 확장자·크기·빈 본문·UTF-8·바이너리/위장 PDF를 검사합니다. 단순 텍스트도 유효한 Markdown이며 특정 제목 형식을 강제하지 않습니다. 회원의 본문 직접 입력은 유지합니다.
- `POST /api/v1/local-data/convert-resume`로 검사를 통과한 파일을 전달합니다. 서버 변환기의 기존 PDF/DOCX/TXT/MD 호환 기능과 백엔드 검증은 변경하지 않았습니다. 파일 선택 제한은 클라이언트 사용성 검사이며 서버 보안 검증을 대신하지 않습니다.
- 인증된 업로드: 변환된 UTF-8 Markdown을 백엔드 `POST /resumes`로 전달합니다. 백엔드는 이 Markdown과 본문을 Supabase의 비공개 `resume-files` Storage·이력서 테이블에 저장합니다. 직접 붙여넣기도 Markdown으로 전달합니다.
- `GET /api/v1/local-data/career-markdown`: `CAREERLENS_JOB_POSTINGS_DIR` 또는 형제 `CareerLens-backend/app/modules/job_postings`에서 숫자 이름의 가상 공고를 읽습니다. 실시간 채용 수집 기능이 아닙니다. 비회원 실제 분석은 선택한 공고 ID로 프론트 서버가 확인한 원문을 사용합니다. 회원의 FastAPI 평가는 백엔드 `/jobs`에 등록된 공고 ID를 요구합니다. 가상 공고라는 표시와 실제 모델 계산 여부는 별개입니다.
- 같은 폴더의 `00_목록.md`에 있는 **직무 유형**을 프론트 서버가 읽어 분류합니다. 공고 선택의 기본 범위는 같은 분류이며, 선택한 직무만/전체 공고로 전환할 수 있습니다. 현재 원본은 100개·11개 분류이며 `AI 모델 서빙 최적화 엔지니어`의 `플랫폼·서빙` 분류는 11개입니다. 로그인 후에는 실제 백엔드 등록 공고만 표시하므로 개수는 등록 현황에 따릅니다. 적합도 추천 순위는 아닙니다.
- `server.py` 변경은 프론트 서버 재시작 후 반영됩니다. 목차가 없거나 재시작 전 서버가 분류 정보를 제공하지 않으면 **전체 공고를 표시하고 사유를 안내**합니다. 직접 입력 직무는 기존 키워드 검색을 유지하며 전체 공고 전환도 가능합니다. 분류 원본과 백엔드 소스는 수정하지 않습니다.
- 회원 평가: 인증 후 `/evaluations` 생성 및 진행 조회. `/evaluations/{id}/progress`가 404이면 `/evaluations/{id}`로 전환합니다. `completed` 또는 `partial`을 확인하고 `/result` 및 `/reports/{id}`를 읽어 기존 화면 계약의 `{ report }`로 반환합니다.
- 비회원 평가: 프론트 서버가 기존 파싱·검색·12개 항목 평가·검증·점수 계산 엔진을 실행합니다. 생성·진행 조회는 `/local-guest/analyses`, 결과 연결은 해당 실행의 `/claim`을 사용합니다. 서버가 보고서를 저장한 뒤에만 완료·잠금을 표시합니다. 일반 비회원 분석은 실제 모델을 사용하며, 합성 시연 모드와 구분합니다.
- 취소·화면 이탈: 회원은 `/evaluations/{id}/cancel`, 비회원은 `/local-guest/analyses/{id}/cancel`을 요청합니다. 비회원 생성 응답이 아직 없으면 `/local-guest/analyses/cancel-pending`으로 해당 요청을 취소합니다. 브라우저 요청 중단만으로 서버 평가가 중단됐다고 가정하지 않습니다.
- 결과: 실제 평가 요약·검증 상태·Markdown 영역은 백엔드 점수·근거를 유지합니다. 알려진 상태값은 한글로 표시하고 예상 면접 질문·다음 대화 질문 섹션은 화면에서 숨기며, 저장된 원문은 변경하지 않습니다. `partial`은 **분석 완료 · 일부 확인 필요**로 표시합니다. 분석은 끝났지만 종합점수가 없거나 일부 항목에 검증 참고사항이 있다는 뜻이며, 진행 중이거나 전체 실패라는 의미가 아닙니다. 보류된 종합점수는 `null`이며 0점·평균·무작위 숫자로 채우지 않습니다. 피라미드도 동일한 백엔드 4축 점수를 사용하며 소수점과 0점을 그대로 유지합니다. 미산정 축은 꼭짓점을 만들지 않고 확인된 선·점만 표시합니다. 무작위 점수와 점수 상승 예시는 명시적 데모에서만 사용합니다. 세부 기준·비중·판정·개선 제안도 실제 응답을 사용합니다.
- **저장 보고서 조회:** 실제 결과에는 `자동 저장됨` 상태와 `저장한 보고서 불러오기` 링크를 표시합니다. 헤더의 마이페이지(`#/mypage`)에서도 본인 보고서를 조회합니다. 기존 백엔드 저장 기록과 로그인 후 계정에 연결한 프론트 서버 보고서를 함께 읽습니다. 후자는 `/local-guest/reports`로 본인 결과만 조회·삭제하며 백엔드 저장 완료로 표시하지 않습니다. 시연 결과는 `시연 보고서`로 구분합니다.
- 목록은 본인 평가를 **20개씩** offset으로 조회한 뒤 `completed`·`partial`만 표시합니다. 회사·직무는 저장 당시 보고서 상단의 채용공고·기업 항목에서 읽으며, 항목별 추가 조회는 최대 3개씩 병렬 처리합니다. 정보가 없는 과거 보고서는 `대상 공고 정보 없음`으로 표시하고 현재 브라우저의 선택 공고로 추정하지 않습니다. 날짜·시간(KST), 한글 상태, 짧은 평가 ID도 표시합니다.
- 검색·상태 필터는 현재 불러온 기록에 적용되며, 전체 선택은 필터된 현재 목록만 대상으로 합니다. 다음 구간은 `더 불러오기`로 확인합니다. 프론트 서버에 계정 연결한 보고서는 실제 삭제 API를 사용합니다. 기존 백엔드 보고서는 삭제 API가 없어 삭제할 수 없습니다. 브라우저에서 행만 지워 성공을 가장하지 않습니다.
- `#/reports/{run_id}`는 평가 ID로 과거 결과와 보고서 본문을 읽어 독립적인 열람용 화면을 만듭니다. 열람·목록 복귀가 현재 작업의 이력서, 선택 공고, 편집 내용이나 분석 결과를 덮어쓰지 않습니다. API 대응과 오류 처리는 [저장 보고서 연동 메모](docs/api/report-save-handoff.md)에 정리했습니다.
- **대시보드 임시 공개 범위:** `#/admin` 화면과 `/admin/evaluation-performance` 조회 API는 로그인·관리자 권한 없이 열립니다. 로그인한 회원은 마이페이지 버튼으로도 접근합니다. 이 대시보드 조회에만 제한을 해제하며 개인 이력서·보고서와 쓰기 기능의 기존 인증·소유권 검사는 유지합니다. 공개 조회 성공을 관리자 권한으로 판단하지 않습니다. 대시보드는 실행·입력·단계별 시간·점수·검증·모델 사용량·보고서 저장의 7개 영역을 갖추며, 현재 API가 반환하는 최근 실행·시간 통계를 연결합니다. 미제공 지표는 미수집/미측정으로 표시합니다. 상세 규격은 [관리자 대시보드 연동 메모](docs/api/admin-dashboard-handoff.md)에 정리했습니다.
- 저장 보고서 선택은 왼쪽 사이드바에서 열고 닫습니다. 서버 목록 순서를 유지하고 현재 보고서는 초록 테두리·문구로 구분합니다. 다시 열 때 현재 보고서 위치를 복원하며 새 분석 후 목록도 갱신합니다. 회원 탈퇴 기능은 현재 구현 범위에서 제외합니다.
- 기존 형식 보고서를 자동 복원하지 못해도 로그인과 새 분석 준비는 계속됩니다. 서버 오류 원문과 진행 진단 정보는 사용자에게 노출하지 않으며, 통제된 안내와 다시 시도 방법을 표시합니다.

백엔드 워커는 프론트 버튼이 직접 띄우지 않습니다. API와 별도 프로세스로 실행돼야 합니다. 필요한 DB 마이그레이션·체크포인트 초기화는 백엔드 운영 준비이며, 파일을 pull했다는 이유만으로 적용됐다고 간주하지 않습니다. 이 프론트 연결 작업은 백엔드 소스와 원격 DB 스키마를 수정하지 않습니다.

## 화면과 모션

공통 메뉴는 이력서·채용공고·모의 지원이며 희망 직무는 채용공고의 내부 단계입니다. 눈 로고나 Career Lens 로고명을 누르면 홈(기존 소개 화면)이 열리고 기존 소개 모션·건너뛰기·자동 이동이 그대로 작동합니다. 일반 페이지 배경의 점·선·가지·원 모션과 그에 따른 반투명 패널 규칙을 제거했습니다. 공고 탐색에서는 원본 목차의 직무 유형으로 분류해 필터링합니다.

분석할 때 흰색 바탕에서 동공이 확대되고, 눈 위 윤곽은 왼쪽→오른쪽, 아래 윤곽은 오른쪽→왼쪽으로 그려집니다. 윤곽과 동공은 **같은 평면**에서 **세로축(Y축)을 중심으로 오른쪽으로 40초에 한 바퀴씩 회전**합니다. 90°의 얇은 옆면에서 로고로 전환해 180°에서 **Career Lens**가 정상 방향으로 보이고, 270°에서 눈으로 전환해 360°에서 눈 정면으로 돌아옵니다. 두 면은 한 캔버스에서 그리고 옆면에는 가는 빛을 이어, 동시에 사라지는 구간을 없앴습니다. 로고 글자는 균일하고 은은한 푸른빛 윤곽으로 그려지며 회전을 유지합니다. 글자 위를 움직이는 빛점과 짧은 잔광은 표시하지 않습니다. 동공 자체의 24초 회전은 별도로 유지합니다. 두 점선 링은 서로 다른 주기로 감속·역회전하고, 안쪽 분절 링은 천천히 돌며 순서대로 점등합니다. 중앙 광원은 원형 테두리 없이 부드럽게 빛납니다. **진행률은 눈 아래에서 회전하지 않고 표시**됩니다. 서버가 100%를 보내도 최종 보고서 수신과 전환 준비가 끝나기 전에는 결과 화면을 열지 않습니다. 회원은 백엔드, 비회원은 프론트 서버가 반환한 실제 progress_percent를 사용하며 평가 점수가 아닙니다. 진행률이 제공되지 않으면 확인 중으로 표시하고, 모션 타이머가 숫자를 덮어쓰지 않습니다. 명시적 데모만 시각적 진행률을 사용합니다. 최초 분석은 최소 4초와 실제 성공을 확인한 뒤, 빛이 보고서 상단 중앙에서 양옆 테두리로 이어집니다. 비회원 결과의 인증 후 잠금 해제에서는 이 로딩·전환을 다시 재생하지 않습니다.

[선택된 디자인](docs/product/selected-design.md), [구현된 흐름](docs/product/implemented-flow.md)을 참고하세요. `/motion-preview`와 `/design-lab`은 이전 모션의 합성 비교실이며 현재 로딩 UI와 다를 수 있습니다. 실제 평가 API를 호출하지 않습니다. 보고서는 브라우저 열람용이고 인쇄·PDF 다운로드 버튼은 제공하지 않습니다.

## 이전 계약의 보존 범위

기존 OpenAPI 1.7.1 snapshot과 쿠키·CSRF·워크스페이스·비회원 claim 코드는 이전 백엔드 연결 및 회귀 검증을 위해 보존합니다. 이것이 현재 FastAPI에 같은 endpoint가 존재한다는 뜻은 아닙니다. 이전 OAuth·비밀번호 재설정, 서버 SQL guest retention, 관심 공고·직접 입력·가상 이력서 관련 계약은 [API 문서의 이전 계약 부분](docs/api/contract-workflow.md)에 남겨 둡니다.

레거시 쿠키 모드에서는 `PUBLIC_ORIGIN`이 브라우저 origin과 같아야 하며 프록시는 쿠키·`X-CSRF-Token`·`Origin`을 전달합니다. 응답 쿠키는 Domain만 제거하고 Secure/HttpOnly/SameSite/Path를 유지합니다. OAuth callback은 실제 해당 API를 제공하는 구형 서버에서만 유효합니다. HTTPS 인증서 검증을 끄지 않습니다.

## 코드와 검증

`src/app`은 라우팅·상태, `src/pages`는 페이지 조합, `src/features`는 기능·모션, `src/shared/api`는 클라이언트·어댑터, `server.py`는 정적 서버·같은 출처 프록시, `resume_conversion.py`는 로컬 문서 변환을 담당합니다. `guest_analysis_engine.py`는 기존 백엔드 엔진을 사용하는 비회원 계산, `guest_analysis_service.py`는 임시 저장·인증 확인·계정 연결을 담당합니다.

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -p test_server.py
node --test tests/unit/*.test.mjs
node scripts/sync-api-contract.mjs --check
```

서버 테스트와 어댑터 테스트는 합성 입력·가짜 API로 실행하며 실제 DB·자격증명·모델 호출을 필요로 하지 않습니다. snapshot 검사 성공은 과거 계약 파일의 해시 검증이며 현재 FastAPI의 실제 호환성을 보증하지 않습니다. Node.js는 테스트와 모션 소스 재빌드에만 필요합니다.

공개 배포는 별도 작업입니다. [이전 배포 준비 안내](infra/deploy/README.md)의 레거시 인증·저장소 설명은 현재 FastAPI 운영 설정과 구분하세요.

## 작동 흐름 보기

`마이페이지 → 대시보드 → 실시간 이용 흐름 보기`를 누르면 현재 앱 탭에 연결된 관찰 화면이 새 탭으로 열립니다. 공개 대시보드 `#/admin`에서도 같은 버튼을 사용할 수 있습니다. 원래 앱을 사용하면서 실제 행동, API 왕복 시간, 서버가 보낸 평가 단계와 저장 응답을 확인합니다. 앱 새로고침 후에도 같은 관찰 창에 다시 연결되며, 밝게·어둡게 전환할 수 있습니다.

`/?view=flow`를 직접 열면 실제 요청을 실행하지 않는 가상 시연 창이 열립니다. 회원가입·계정 / 이력서·저장 / 직무·채용공고 / 분석·예외 처리 / 저장 보고서 / 운영 대시보드의 여섯 분류와 검색에서 경우를 선택합니다. 성공뿐 아니라 이메일 확인 대기, 입력 오류, 요청 실패, 취소, 부분 완료, 자료 없음과 접근 불가를 별도 버튼으로 재생합니다. 선택한 경우에 필요한 노드와 연결선만 표시하며, 회원가입의 회원 정보 저장, 비회원 이력서의 브라우저 임시 보관, 기존 보고서의 조회처럼 서로 다른 경로를 구분합니다.

각 경우는 필요한 계정·파일·선행 상태가 준비된 것으로 가정하므로 어떤 버튼이든 독립적으로 실행할 수 있습니다. 실제 계정 생성·로그인·API 호출·데이터 저장·분석은 하지 않습니다. 다른 경우를 누르면 이전 기록을 지우고 전환하며 일시정지·다시 재생·초기화와 전체 성공 흐름 재생을 지원합니다.
