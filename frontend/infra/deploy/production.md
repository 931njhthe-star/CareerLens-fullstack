# 원본 백엔드와 프론트엔드 배포

2026-10-13 KST. 백엔드는 `3863f6eb65775a6483d35ca02b4030c876cfa16c` 원본을 유지합니다.
이 구성은 배포 파일이며 실제 클라우드 배포 완료를 뜻하지 않습니다. 백엔드 패치를 적용하지 않습니다.

## 실행 구성

브라우저 → HTTPS Caddy → Flask/Waitress 프론트 → 원본 FastAPI → Supabase.
회원 분석은 원본 워커가 처리합니다. 비회원 분석은 프론트 서버가 원본 백엔드 엔진을
호출해 실제 계산하고, 결과를 개인 SQLite 저장소에 보관한 뒤 인증된 계정에 연결합니다.
프론트는 백엔드 소스·관리자 설정·DB 스키마를 변경하거나 관리자 권한을 사칭하지 않습니다.

- 같은 상위 폴더에 `CareerLens-frontend`, `CareerLens-backend` 저장소를 둡니다.
- Docker 이미지는 두 저장소의 필요한 소스와 잠금 의존성만 포함합니다. 개인 `.env`, DB, 로그, Git 기록은 제외합니다.
- 외부 포트는 Caddy 80/443이며 내부 API·프론트 포트는 공개하지 않습니다.
- Redis·공용 흐름 수집 서비스는 포함하지 않습니다.
- EXE는 로컬 실행용입니다. PC 종료 후에도 운영하려면 별도 배포 서버가 필요합니다.

## 적용

1. `.env.production.example`을 `.env.production`으로 복사하고 실제 도메인·Supabase·모델 설정을 입력합니다. 키는 Git에 올리지 않습니다.
2. DNS와 HTTPS, Supabase 인증 Site URL/Redirect URLs를 설정합니다.
3. 팀의 기존 DB 스키마·RPC·체크포인트·공고 데이터가 준비되었는지 확인합니다. 이 구성은 DB 변경을 자동 실행하지 않습니다.
4. `CareerLens-frontend/infra/deploy`에서 실행합니다.

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

5. 일반 회원으로 로그인해 마이페이지의 대시보드·이용 흐름을 확인합니다. 프론트 대시보드는 관리자 설정 없이 본인 실행 기록을 조회합니다. 비회원 데이터 조회는 401입니다.

## 현재 제공 범위

- 대시보드는 원본 API의 소유권 검사가 적용되는 `/evaluations`를 이용한 **현재 계정의 최근 실행 표본**입니다. 전체 계정 집계가 아닙니다. 원본 API가 제공하지 않는 노드·도구·토큰·버전·단계 소요시간은 값을 만들지 않고 미제공으로 표시합니다.
- 원본 `/admin/evaluation-performance`의 관리자 접근 정책은 바꾸지 않습니다. 프론트 서버의 같은 경로가 회원용 호환 응답을 구성합니다.
- 이용 흐름은 연결된 브라우저/탭에서 관측한 이벤트 범위입니다. 다른 기기·모든 사용자 요청을 서버 전체에서 수집하는 기능은 현재 원본 API에 없습니다.
- 원본 워커는 별도 실행이 필요합니다. API 건강 응답은 워커·DB·모델 정상 동작을 증명하지 않습니다. 워커 정지 시 분석은 대기할 수 있으므로 운영에서 프로세스를 감시합니다.
- `guest-data` 볼륨은 인증 후 다시 보는 비회원 결과를 포함합니다. 재배포 시 유지해야 하며 `docker compose down -v`는 데이터를 삭제합니다.
- 현재 프론트는 한 인스턴스/한 프로세스만 지원합니다. 비회원 SQLite와 작업 큐가 해당 프로세스에 있으며 기본 계산 2건·대기 4건입니다. 프론트 재시작 시 진행 중 계산은 재시도가 필요하고 완료 결과는 볼륨에 남습니다.
- 회원 워커는 기존 DB·모델 사용량 한도에 맞춰 운영합니다. 계정별 최신 분석 우선 정책도 원본 동작 그대로입니다.

## 검증 범위

최신 재검증은 원본 백엔드 27개, 프론트 Python 전체 113개와 하위 검사 171개, JavaScript 866개를 통과했습니다.
여기에는 회원 대시보드 소유권·정보 노출, 공고 캐시 인증·격리·실패 복구, 창별 추적·접근 제어 검사가 포함됩니다. [최종 검증 기록](../../docs/verification/release-20261013-0925.md)을 참고하세요.
실제 Docker 빌드·TLS·운영 DB·이메일 인증·유료 모델 분석·운영 부하는 별도 검증이 필요합니다.
