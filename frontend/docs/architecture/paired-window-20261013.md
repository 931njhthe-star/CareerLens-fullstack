# CareerLens 창별 1:1 이용 흐름 아키텍처

2026-10-13 07:19 KST 개정. 백엔드 기준: 3863f6eb65775a6483d35ca02b4030c876cfa16c.

작업 창 A에서 연 관찰창 A는 A의 안전한 브라우저 이벤트만 받습니다. B/B, C/C도 독립적입니다. 각 쌍의 전달은 같은 브라우저·프로필·출처의 BroadcastChannel로 이루어지고 서버에 공동 관측 기록을 저장하지 않습니다. 새 창의 활동으로 자동 선택하지 않습니다. 관찰창은 실제 로그인 회원만 열 수 있으며 인증 정보는 URL이나 이벤트에 넣지 않습니다.

그림의 작업창과 관찰창은 하나의 쌍 노드로 표현합니다. FastAPI에서 워커로 향하는 선은 직접 HTTP 호출이 아닌 Supabase DB 작업큐를 통한 등록·조회 관계입니다. 로컬은 프론트 포트5300을 사용하며 배포는 HTTPS 진입점을 사용합니다. HTTPS 서버가 창별 관찰 이벤트를 중계하는 것은 아닙니다.

회원 분석은 원본 API와 워커, 비회원 계산은 프론트 서버에서 원본 분석 엔진을 가져와 수행합니다. 로그인 후 이미 계산한 비회원 결과를 계정에 연결합니다. 프론트 대시보드는 로그인한 본인의 기존 평가 API 범위만 보여주며, 추가 내부 계측을 생성하지 않습니다.

원본 창에서 페이지 이동·새로고침 후 연결을 이어가며 새로 연 다른 창은 별도 쌍이 됩니다. 원본 창을 닫으면 연결 종료를 알리고 다른 창으로 전환하지 않습니다. 브라우저 백그라운드 절전으로 전달이 늦어질 수 있습니다. 분석 서버·워커의 정상 가동은 별도 조건입니다.

현재 비회원 저장과 큐는 프론트 한 인스턴스·한 프로세스 전제입니다. 실제 운영 주소/TLS/부하 검증과 비용 발생 분석은 별도 검증 항목입니다. Redis 및 전체 사용자 관찰 기능은 이번 설계에서 제외했습니다.
