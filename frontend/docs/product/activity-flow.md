# 작동 흐름 관찰 화면

## 방향

Mode: Operate / Experience. 기존 프로젝트의 별도 관찰 도구다. 사용자가 제공한 7장의 이미지를 기준으로 어두운 노드 카드, 곡선 연결선, 움직이는 빛을 Canvas와 HTML로 구현한다.

기존 앱의 흰색·파란색 화면, CareerLens 로고, 주요 메뉴와 분석 동작을 유지한다. 마이페이지의 대시보드 안에 `실시간 이용 흐름 보기` 링크를 제공한다. 관찰 도구는 어두운 모드를 기본으로 제공하며 밝은 모드도 선택할 수 있다. 배경과 스타일·변수는 `flow-mode` 전용 범위에 둔다. 기존 전역 토큰을 교체하거나 새 디자인 시스템을 만들지 않는다.

지도는 사용자 행동 → API 요청 → 분석 처리 → 데이터·결과의 4열로 구성한다. 실제 관찰의 연결선은 처리 관계를 표현하며 실제 내부 호출 경로나 실행 증거를 뜻하지 않는다. 관측 이벤트를 받으면 해당 카드와 연결선에 빛이 움직인다. 가상 시연에서는 선택한 경우에 쓰이는 노드와 연결선만 표시하고, 해당 이벤트의 출발 단계에서 빛이 이동한다. 회원가입이나 기존 보고서 조회를 분석 대기열에 연결하지 않는다. 하단에는 이벤트 로그, 최근 16개 API 요청의 왕복 시간 그래프, 선택 단계의 상세를 배치한다.

2026-10-12 비회원 분석 경로 보완: 비회원도 인증 전에 프론트 서버에서 실제 계산을 완료한다. 흐름 화면은 **분석 완료 → 프론트 서버 결과 저장 → 잠금·인증 대기 → 인증 계정 연결 → 실제 보고서 표시**를 구분한다. 잠금 화면 도착을 모의지원 전체 완료로 취급하지 않는다. 기존 네 열과 밝은·어두운 테마를 유지하고, 관련 카드 선택 시 원래 세부 기록과 측정 시간을 확인한다. 중복되는 큰 상단 비회원 요약은 제거했다.

### 카드 수와 통합 기준

비회원 보완 전 `FLOW_COLUMNS`는 24개(사용자 5·API 5·분석 11·데이터 3)였지만 실제 관찰 화면은 공통 기능 16개를 더해 **40개**를 표시했다. 추가된 비회원 관측 지점 9개를 별도 카드로 노출하면서 49개로 늘어났다. 사용자의 “이전보다 줄이지 말고 최대 4개 추가” 기준은 실제 노출된 40개이며, 현재는 **41개(12·10·12·7), 이전보다 1개 추가**로 고정한다. 24개만 원본으로 보고 화면을 축소하지 않는다.

| 원본 세부 이벤트 | 표시 카드 |
| --- | --- |
| 회원 분석, 비회원 서비스 확인·생성·진행 조회 | 분석 요청 |
| 회원 보고서, 비회원 결과 연결·계정 보고서 조회·삭제 | 보고서 요청 |
| 회원 서버 저장, 비회원 프론트 서버 저장 | 결과·자료 저장 |
| 잠금·인증 대기, 저장 결과 계정 연결 | 결과 잠금·계정 연결 — 추가된 카드 1개 |
| 실제 보고서 표시, 인증 후 표시 시간 | 보고서 표시 |
| 브라우저 입력 보관, 비회원 만료·폐기 확인 | 브라우저 보관·정리 |

카드만 통합하며 원본 이벤트 식별자·출처·시간·진행률·로그는 삭제하지 않는다. 카드 선택 시 `통합된 세부 기록`에 각 관측 지점을 보여준다. 서버 분석 시간은 분석 카드 상세에, 인증 후 실제 표시 시간과 3초 목표 판정은 보고서 표시 카드 상세에 둔다. 회원·비회원의 최근 세부 작업 이름을 카드 설명에 표시해 저장 위치를 혼동하지 않게 한다. 시연은 전체 41개 안에서 해당 경우에 사용하는 카드만 표시한다.

`projectFlowNode`와 `projectFlowEdges`는 내부 이벤트를 표시 카드에 연결한다. 같은 카드 안의 이동과 중복 연결선은 별도 선으로 늘리지 않는다. 모션에는 투영된 카드 식별자를 전달한다. `syncActive`는 `pending/running/queued`의 정적인 강조만 유지하며 움직이는 빛을 만들지 않는다. 새 요청·응답·진행 이벤트만 짧은 효과를 발생시킨다. 동일 이벤트 재수신, 주기적 현재 상태 동기화, 새로고침으로 과거 빛을 재생하지 않으며 완료·실패·취소 후 활성 강조를 비운다.

## 열기와 사용

1. CareerLens 앱의 `마이페이지 → 대시보드 → 실시간 이용 흐름 보기`를 누른다. 새 탭에서 `실시간 · 연결된 탭` 모드가 열린다. 공개 대시보드 `#/admin`에 직접 들어가도 같은 버튼을 사용할 수 있다.
2. 원래 앱 탭에서 화면 이동, 로그인, 이력서 준비, 직무·공고 선택 등을 진행한다. 관찰 화면은 그 탭의 이벤트만 받는다.
3. 노드를 선택하면 정보 출처, 최근 이벤트 시각, 요청 시간, 제공된 분석 진행률을 확인할 수 있다. 화면을 연 상태와 업무 완료는 별도 상태로 표시한다.
4. 상단 `밝게 / 어둡게` 버튼으로 배경·카드·연결선·로그·그래프의 색을 함께 바꾼다. 모드를 바꿔도 시연 진행, 일시정지와 기록은 유지한다. 선택은 같은 브라우저·출처의 다음 방문에도 적용된다.

연결 링크는 `/?view=flow&stream=…` 형식이다. 앱 탭의 sessionStorage에 임의 식별자만 보관하므로 원래 앱을 새로고침해도 열린 관찰 창이 다시 연결된다. 이벤트 기록 자체는 저장하지 않으며 새로고침하면 새 기록으로 시작한다. 원래 탭을 닫거나 연결할 수 없으면 관찰 화면은 연결 대기 상태가 된다. BroadcastChannel을 지원하지 않는 환경에는 대시보드에서 비활성 버튼과 안내를 표시한다. 브라우저 저장소가 막힌 경우에는 새로고침 전까지만 같은 식별자를 사용한다.

로그인한 앱과 관찰 창의 연결 번호가 다르면 로그인 이벤트도 전달되지 않는다. 현재 사용하는 앱의 대시보드에서 이용 흐름 링크를 다시 열어 연결한다. 다른 탭의 기록을 자동으로 섞지 않는다. 같은 연결에서는 인증 이벤트를 받는 즉시 회원·비회원 헤더를 갱신하고, 인증 카드는 확인된 현재 세션을 표시한다. 최근 화면 이동이나 요청 실패는 별도 설명과 로그에 남기므로 로그인 상태를 덮어쓰지 않는다.

`/?view=flow`를 직접 열면 `시연 · 가상 이벤트` 모드로 시작한다. 연결된 관찰 화면에서도 모드를 전환할 수 있다. 시연의 빛, 로그, 시간, 진행률은 모두 고정된 가상 시나리오이며 실제 API·인증·분석을 실행하지 않는다. 시연 이벤트는 실제 관찰 기록에 섞이지 않는다.

시연 창은 자동 실행 없이 버튼 선택을 기다린다. 여섯 기능 분류 또는 전체 목록에서 경우를 고르고, 검색으로 원하는 상황을 찾는다. 각 버튼에는 성공·실패·대기 등 결과와 시작 조건이 있다. 시작 조건은 시연이 제공하는 가정이므로 실제 로그인·파일 첨부나 다른 시연의 선행 실행은 필요 없다. 다른 경우를 누르면 이전 시연과 기록을 정리하고 선택한 경우로 전환한다.

| 분류 | 시연하는 경우 |
| --- | --- |
| 회원가입·계정 | 회원가입 성공·이메일 확인 대기·입력 오류·요청 실패, 로그인 성공·실패, 로그아웃, 세션 갱신 성공·실패 |
| 이력서·저장 | 회원·비회원 첨부, 본문 수정·저장, 파일·내용 오류, 변환·저장 실패, 임시 보관 만료, 로그인 후 임시 이력서 연결·만료, 작업공간 초기화 |
| 직무·채용공고 | 희망 직무 선택·목록 조회, 공고 상세·선택, 검색 결과 없음·조회 실패, 시연 계정의 북마크 저장·해제와 직접 입력 공고 만들기·수정·삭제, 실제 회원의 공고 쓰기 차단 |
| 분석·예외 처리 | 회원 분석 성공, 비회원 계산·저장 후 로그인/가입 결과 표시, 잠금·이메일 인증 대기, 결과 연결 실패·3초 목표 초과, 임시 결과 만료·취소, 서비스 연결 복구, 공고 먼저 선택 후 첨부, 필수 입력 없음·회원 서버 미등록 공고 차단, 시작·진행 실패, 응답 대기 시간 초과, 부분 완료 |
| 저장 보고서 | 목록 조회·기존 보고서 다시 열기, 저장 기록 없음, 접근 불가, 아직 미완료, 조회 중 세션 만료, 분석 완료 후 최종 보고서 조회 실패 |
| 운영 대시보드 | 공개 대시보드·기간 조회, 기록 없음·조회 실패, 가상으로 불러온 기록의 상태 필터·실행 상세 |

`분석 성공·보고서 결과 확인`은 약 9초 동안 회원 분석 대기·해석·진행률·검증·저장·보고서 표시를 가상으로 재현한다. `전체 성공 흐름`은 비회원 준비부터 로그인 전 계산·프론트 서버 결과 저장, 로그인 후 기존 보고서 표시까지 이어진다. 모든 시연의 상태·요청 시간·분석 시간·인증 후 표시 시간은 고정된 가상 예시다. 시연의 재생 시간은 설명을 위해 압축되며 실제 서비스 성능이나 3초 목표 달성을 증명하지 않는다.

### 경우별 저장과 결과의 의미

- 회원가입 성공은 가입 요청 → 회원 정보·프로필 저장 → 로그인으로 이어진다. 이메일 확인이 필요한 가입은 저장 후 확인 대기에서 끝나며 로그인 완료로 표시하지 않는다. 입력 오류나 가입 요청 실패는 저장 완료 단계로 가지 않는다.
- 회원 이력서는 변환 후 서버 저장으로, 비회원 이력서는 변환 요청 후 브라우저 임시 보관으로 이어진다. 실제 서비스의 비회원 임시 보관 기한은 첫 유효 첨부부터 30분이며, 시연의 만료 버튼은 이미 만료된 예시 상태를 즉시 재생한다. 로그인 후 유효한 임시 이력서를 연결할 때만 서버 저장 경로를 사용한다.
- 로그아웃은 브라우저 세션을 비운다. 희망 직무 선택은 브라우저 보관 경로를 사용한다. 북마크·직접 입력 공고 쓰기는 앱의 명시적 시연 계정에만 제공되는 브라우저 보관 기능을 가정하며 서버 DB 쓰기로 표현하지 않는다. 실제 회원에게는 현재 비활성인 기능이므로 별도의 쓰기 차단 경우로 구분한다. 작업공간 초기화는 현재 이력서와 작업 상태의 정리이며 회원 탈퇴나 모든 보고서 삭제가 아니다.
- 저장 보고서 목록과 다시 열기는 저장 자료를 읽는 경로다. 새 분석이나 재저장을 시작하지 않는다. 분석 실패·취소는 성공 보고서를 만들지 않고, 분석 완료 후 보고서 조회가 실패하면 진행률이 100%여도 보고서 표시 완료로 넘어가지 않는다. 부분 완료는 실패와 별도로 표시하고 누락 점수를 채우지 않는다.
- 비회원 계산은 서버가 검증한 공고와 준비된 입력으로 프론트 서버의 기존 평가 엔진을 실행하는 경로다. 완료 결과는 프론트 서버의 비공개 저장소에 보관하고 인증 전에는 본문·점수를 브라우저에 전달하지 않는다. 로그인이나 즉시 인증되는 가입 성공 후 `결과 연결`을 거쳐 재분석 없이 현재 보고서를 표시한다. 이메일 인증이 필요한 가입은 인증 대기에서 멈추며 임시 보관 기한이 연장되지 않는다.
- 이력서·희망 직무·공고를 준비하는 순서는 유동적이다. 공고를 먼저 선택한 뒤 이력서로 돌아가 첨부해도 선택을 유지한다. 서비스 연결 실패는 분석 성공으로 표시하지 않으며 버튼에서 연결을 재확인한 뒤 분석할 수 있다. 취소·만료·결과 연결 실패는 실제 보고서 표시와 구분하고, 3초를 초과한 결과 연결도 재분석으로 표현하지 않는다.
- 운영 대시보드는 공개된 읽기 전용 조회를 가정한다. 조회한 기록을 필터링하는 경우에는 추가 요청이 없으며, 조회 실패를 정상적인 0건·0값으로 표시하지 않는다.

모든 시연은 고정된 가상 이벤트다. 실제 API, 브라우저 저장소, 계정·이력서·공고·보고서·운영 데이터에 접근하거나 변경하지 않는다. 시연 버튼을 눌러 실제 비회원 분석을 실행하거나 보고서를 만들지 않는다. OAuth, 비밀번호 재설정, 회원 탈퇴 등 구현하지 않은 기능을 추가했다고 표현하지 않는다.

실제 대시보드의 실행 상세는 목록 조회와 별도로 `GET /admin/evaluation-performance/{실행 ID}`를 요청한다. 실시간 관찰에서는 이 요청도 `운영 기록 요청`의 왕복 시간과 상태로 표시한다. 위 표의 실행 상세 시연은 이미 준비된 가상 기록을 보여주는 예시이며 실제 상세 API를 호출하지 않는다.

## 데이터 범위

- 관찰 메타데이터는 같은 브라우저·출처의 BroadcastChannel로 전달한다. 원격 텔레메트리 전송이나 별도의 수집 서버가 없으며 기존 프론트·API·워커의 서버 구성과 개수를 바꾸지 않는다.
- 기록은 메모리에 최근 100개와 각 노드의 최신 상태만 보관하며 브라우저 저장소나 파일에 영구 저장하지 않는다. 단계, 상태, 출처, 관측 시각, 요청 방식·시간, 유효한 전체 진행률, A1~D3 항목 코드와 비회원·회원·시연 여부만 다룬다. 계정 식별 정보, 파일명, 이력서·공고 본문, 요청·응답 원문, URL, 토큰, 서버 오류 원문은 기록하지 않는다.
- 화면 밝기 선택만 별도 localStorage 키 `careerlens.flow.theme.v1`에 저장한다. 저장소를 사용할 수 없으면 현재 화면에서는 전환하되 다음 방문까지 보관하지 않는다. 이 설정은 시연 이벤트나 실제 앱의 데이터와 독립적이다.
- API 시간은 실제 네트워크 요청별로 브라우저 요청 시작부터 응답 처리 완료까지 측정한다. 네트워크 왕복과 응답 처리를 포함하므로 서버 내부 계산 시간이나 어댑터 작업 전체의 처리 시간으로 해석하지 않는다. 측정하지 않은 시간은 `미측정`으로 표시한다.
- 비회원 분석 시간은 프론트 서버의 실제 엔진 수행 시간 `analysis_duration_ms`를 사용한다. 대기열·로그인 대기 시간을 포함하지 않는다. `인증 완료 → 보고서 표시`는 로그인·가입 API 성공 직후부터 인증 확인, 기존 결과 연결, 실제 보고서 DOM 표시까지의 브라우저 실측이다. 네트워크 API 차트에 이 두 시간을 섞지 않는다. 실제 보고서가 표시됐고 유효한 측정값이 있을 때만 `3초 이내 표시 확인` 또는 `3초 목표 초과`를 표시한다. 미측정·진행 중·실패·이전 저장 보고서의 조회에서 목표 달성을 추정하지 않는다.
- `/local-guest/capabilities`, 분석 생성·상태 확인, 취소, 결과 연결, 계정 보고서 조회·삭제 요청을 각각 서비스 확인·비회원 분석·취소·결과 연결·비회원 보고서 요청으로 분류한다. 비회원 내부 이벤트에는 `execution: guest`를 붙여 프론트 서버 응답임을 구분한다. 비회원 결과 저장은 `guest_store`이고 회원 워커의 백엔드 저장 `database`와 구별한다.
- 분석 진행률은 서버가 제공한 유효한 값만 표시하며 없으면 `미제공`이다. 대기 단계의 임시 0을 측정값으로 표시하지 않는다. 진행률 100%와 보고서 표시 완료는 별도 이벤트다.
- 워커가 실제로 제공한 진행 이벤트만 허용된 단계로 변환한다. 이력서 해석 → 공고 해석 → 근거 검색 준비 → 4개 영역·12개 항목 병렬 평가 → 교차 검증·필요 항목 재평가 → 점수 계산 → 결과·보고서 저장의 구조를 반영한다. 영역 카드에는 최근 항목 코드와 상태를 함께 표시하며 한 항목 완료를 영역 전체 완료로 해석하지 않는다. 단계별 진행률은 제공되지 않으므로 전체 분석 노드에만 서버의 전체 진행률을 표시한다.
- 회원가입과 이력서 저장은 성공 응답의 식별자가 확인되면 `서버 저장 응답`에 표시한다. 이 응답은 DB 내부 세부 처리 시간의 계측을 뜻하지 않는다. `브라우저 보관`은 실제 sessionStorage 저장·삭제 뒤에만 갱신한다. `데이터 저장`은 워커의 최종 보고서 저장 이벤트를 바탕으로 한다. 미제공 단계나 기록 보관의 별도 계측은 `미수집`이며 앞 단계의 완료로 추정하지 않는다.
- 비회원 `프론트 서버 결과 저장`은 실제 저장이 완료된 서버 이벤트로만 표시한다. 브라우저 입력 보관, 서버의 최대 30분 임시 결과 보관, 인증 계정에 연결된 프론트 서버 보고서는 별도 책임이다. 계정 연결이 기존 백엔드 보고서 DB로의 이관을 뜻하지 않는다. 관측되지 않은 내부 단계는 `비회원 분석 기록 대기` 또는 `회원 워커 기록 대기`, 비회원 결과 저장은 `프론트 서버 저장 기록 대기`로 출처를 구분하며 실행 실패나 정상 생략으로 단정하지 않는다.
- 관찰 범위는 연결된 앱 탭 1개다. 서비스 전체 트래픽, 전체 접속자, 다른 사용자 행동을 집계하지 않는다. 로그 영역은 관측 이벤트 기록이며 실제 서버 터미널이나 명령 실행기가 아니다.

## 상호작용과 접근성

노드는 키보드로 선택할 수 있고 상태를 색과 문구로 함께 표시한다. `동작 줄이기`는 빛의 움직임을 멈추며 이벤트 수신과 상태 갱신은 유지한다. 초기 설정은 `prefers-reduced-motion`을 따른다. 시연은 일시정지·이어보기·다시 재생을 제공하며 `초기화`하면 기록과 움직임을 지우고 버튼 선택 대기로 돌아온다.

화면이 보이지 않으면 Canvas 애니메이션과 시연 진행을 멈춘다. 기존 다중 연결선·빛 입자의 꼬리·노드 주변 확산 효과는 새 이벤트 때만 짧게 표시한다. 새 이벤트 없이 대기·진행 상태만 유지되면 연결선과 테두리에 움직이는 빛이 없어야 한다. 숨김·연결 종료·12초 이상 연결 응답 부재 시 남은 효과를 버리고, 돌아왔을 때 과거 효과를 재생하지 않는다. Canvas는 최대 30fps·약 420만 픽셀로 제한하고 움직이는 효과가 없으면 프레임을 예약하지 않는다. 이동하는 빛과 강조 효과의 개수를 제한하고 창을 떠날 때 타이머·채널·관찰자를 해제한다. 좁은 화면에서는 흐름 지도 안에서만 가로 스크롤하며 로그·그래프·상세는 세로로 배치한다. 가상 시연 중에는 진행 단계가 지도 밖으로 벗어나면 그 단계로 가로 이동하고, 동작 줄이기 설정에서는 즉시 이동한다.

## 구현과 회귀 확인 범위

`src/features/activity-flow/events.js`는 제한된 메타데이터와 탭 연결을, `catalog.js`는 관측·시연 노드와 상태 검증을, `viewer.js`와 `motion.js`는 관찰 화면과 Canvas를 담당한다. 시연 전용 노드는 실제 관찰 입력으로 받지 않는다. `src/app/main.js`는 `view=flow`에서 관찰 화면만 시작하고 일반 앱에는 실행 링크와 관측 지점을 연결한다. `src/shared/api/client.js`는 실제 요청의 시작·완료·실패·취소를 기록한다.

`backend-progress.js`는 현재 백엔드가 발행하는 고정 단계·상태·메시지를 해석해 원문 없이 노드·상태·항목 코드만 반환한다. 알 수 없는 이벤트는 버린다. 어댑터의 기존 약 2초 진행 조회를 재사용하므로 별도 서버나 관찰용 반복 조회를 추가하지 않는다. 완료·부분 완료 상태에서 진행 이벤트가 100개로 꽉 찬 페이지이면 최대 9페이지를 추가 조회해 마지막 저장 이벤트를 회수한다. 추가 계측 조회가 실패해도 정상적인 최종 보고서 조회는 계속한다. 새 분석 시작 시 이전 워커 노드 상태를 지우고, 같은 항목의 반복적인 진행 중 알림은 중복 기록하지 않는다.

`demo.js`는 기능 분류, 시작 조건·결과가 있는 독립된 경우별 시나리오와 순수 재생기를 제공한다. 경우별 노드와 연결선은 시나리오에서 만들며 재생기는 주어진 시간만큼 가상 이벤트를 내보낸다. 네트워크·인증·저장소에 접근하지 않는다. `activity-flow-demo` 테스트는 개별 실행, 중간 전환, 중복 방지, 일시정지·초기화, 보고서 완료 순서와 실제 이벤트의 분리를 검증한다.

비회원 보완 회귀 검증은 인증 전 계산·서버 저장 순서, 인증 후 재분석 없음, 잠금과 표시 완료 분리, 실패·만료·취소에서 보고서를 만들지 않음, 실제 표시·측정이 없는 3초 달성 문구 금지, 분석·전달 시간을 API 차트에서 제외, 새 실행에서 이전 결과 상태 정리를 포함한다. 카드 통합 검증은 41개 DOM·열별 개수, 모든 원본 이벤트의 표시 대상, 중복·자기 연결 제거, 상세 원본 로그 보존을 확인한다. 모션 검증은 현재 상태 복원·중복 수신 시 정적 유지, 새 이벤트의 유한 효과, 숨김·연결 종료 후 과거 효과 재생 방지를 포함한다. 로그인·가입 제출부터 세션 검증·동일 스트림 수신까지 합성 통합 테스트로 확인하며 유료 모델 호출이나 실사용자의 인증·보고서 데이터를 만들지 않는다.

관련 단위 검증은 `activity-flow-events`, `activity-flow-viewer`, `api-client`와 기존 이용 흐름의 `account-routing`, `auth-callback`, `desired-role-routing`, `direct-report-flow`, `session-expiry` 테스트다. 합성 입력으로 관찰 범위와 회귀를 확인하며 실제 유료 평가나 서버 내부 계측 검증을 뜻하지 않는다.

2026-10-12 초기 관찰 화면 검증에서 관련 단위 테스트 111개가 통과했다. 가상 기능 버튼 추가 후 관련 단위 테스트 118개가 통과했으며 브라우저에서 가상 로그인 완료, 보고서 진행률·완료, 기능 전환, 일시정지·이어보기, 초기화와 1440px·390px·508px 배치를 확인했다. 실제 로그인·파일 업로드·평가는 실행하지 않았다.

같은 날 경우별 시연을 6개 분류·53개 경우와 전체 성공 흐름으로 확장한 뒤 관련 회귀 테스트 129개가 통과했다. 가입 성공·실패·이메일 확인 대기, 비회원 이력서 변환 후 임시 보관, 기존 보고서 조회, 분석 취소와 실시간 전환 시 시연 정리를 브라우저에서 확인했다. 1440px·390px·517px에서 페이지 가로 넘침 없이 표시하며 좁은 화면의 지도는 내부에서 이동한다. 전체 성공 흐름은 약 21초, 분석 성공은 약 9초다.
