# 과정 모션: 실제 적용과 수정 기록

2026-10-09 사용자가 승인한 v8 미리보기의 시각 표현을 실제 웹페이지에 연결한 뒤, 페이지별 진행 단계·콘텐츠 뒤 레이어·흰색 분석 전환을 v9에서 수정했다. 실제 앱은 아래의 페이지 단계와 공통 고정 좌표 모션을 사용한다. 2026-10-08의 물결 게이지·원의 이동·크기 변화 방향과 이전 검토 버전 설명은 수정 기록이며 현재 동작이 아니다. 이 문서의 적용은 로컬 소스와 실행 앱의 연결을 뜻하며, 배포나 Git 업로드를 뜻하지 않는다.

## 현재 실제 웹페이지

모션의 목표 단계는 현재 페이지에 맞추고, 현재 그려진 프레임에서 앞뒤로 이어 재생한다. 저장된 이력서 유무로 단계를 건너뛰지 않는다.

1. 홈·소개에는 점·선·요소·원을 그리지 않는다. 기존 소개 타이머와 건너뛰기는 유지한다.
2. 이력서 첨부 페이지에서 제목과 설명 아래의 푸른 점이 처음 나타난다. 이미 저장된 이력서가 있어도 점에서 시작한다. 업로드·저장 중에는 곡선까지만 진행하며, 이 페이지에서 가지나 원으로 넘어가지 않는다.
3. 희망 직무 페이지에서 곡선이 실행별로 선택한 5개 평가 요소로 갈라진다. 펼쳐진 가지와 요소를 유지하며 아직 원을 형성하지 않는다.
4. 채용 공고 목록·상세·선택 화면에서 요소들이 회전하며 모여 처음 원을 형성한다. 완성된 원은 계속 회전한다.
5. 이전 단계로 돌아가면 현재 프레임부터 역재생한다. 채용 공고 → 희망 직무는 원이 풀려 가지와 5개 요소로, 채용 공고 → 이력서는 원 → 가지 → 곡선 → 점으로 되돌아간다. 전진·역재생 도중 다른 단계를 눌러도 현재 위치와 회전 위상에서 새 목표로 방향을 바꾼다. 완료된 결과 페이지에는 과정 모션을 남기지 않는다.

`journey-motion.js`는 뷰포트에 고정된 배경 레이어(`z-index: 0`)에 `fixed-anchor-study.js`의 v8 장면을 그린다. 페이지 본문·진행표·메뉴는 그 앞의 레이어(`z-index: 1`)에 놓는다. 이력서·희망 직무·채용 공고의 관련 입력 칸과 패널은 흰색 배경 불투명도 80%를 사용하여 뒤 모션이 은은하게 비치도록 한다. 글자나 버튼 전체의 투명도를 낮추지 않는다. 완료된 결과 화면에는 이 반투명 배경 규칙을 적용하지 않는다.

`journey-layout.js`가 실제 화면 크기에 맞춰 점에서 가지로 이어지는 경로와 요소 위치를 배치한다. 과정 페이지 사이에서는 같은 body 캔버스·시드·좌표·회전 위상을 유지하고 목표 시간만 바꾼다. 비동기 공고 로딩이나 제목 교체도 캔버스를 제거하지 않는다. 전진은 타임라인 초당 1.6초, 역재생은 초당 3.2초로 진행하며 단계 생략 없이 목표에서 멈춘다. 점의 점등도 현재 타임라인에 연결하여 복귀 중 원 전체가 깜빡이지 않는다. 홈·인증·완료 결과로 나가면 캔버스를 해제하고, 새 이력서 진입은 다시 점에서 시작한다. 이미 형성된 원은 스크롤해도 같은 화면 위치와 크기를 유지하며 페이지 콘텐츠가 그 앞을 지나간다.

`live-eye-motion.js`의 `liveMotionViewport()`를 과정 모션과 분석 모달이 함께 사용한다. 원 형성부터 분석까지 동공 중심과 반지름은 같은 뷰포트 좌표에서 계산하며, 모달 진입을 위한 이동·축소 handoff는 사용하지 않는다. 브라우저 크기를 바꾸면 두 레이어가 같은 기준으로 함께 반응한다. 점이나 가지 단계에서 분석을 시작한 경우에는 현재 장면을 이어받아 최대 0.9초 안에 원 형성을 마친다.

결과 확인 시 메뉴·진행표·본문·버튼이 460ms 동안 페이드아웃하여 순백색(`#ffffff`) 배경과 회전하는 원만 남는다. 이때 원은 함께 흐려지지 않으며 위치·크기·회전 위상을 유지한다. 이후 균일한 사파이어 링이 0.85초 동안 초당 3.5회전까지 가속한다. 가속 시점부터 위 윤곽은 왼쪽→오른쪽, 아래 윤곽은 오른쪽→왼쪽으로 그린다. 양옆은 주 윤곽 한 줄·연한 보조선 한 줄·옅은 푸른 면으로 단순화했다. 홍채는 동공 안쪽 경계에서 바깥쪽으로 자라는 불규칙한 곡선 섬유가 원본 질감을 드러내며 완성된다. 원본 유리 질감의 양옆, 거울 대칭 꽃잎 패턴, 물결 면과 전체 이미지 페이드인은 사용하지 않는다. 링 몸체는 홍채에 녹아들고, 동공 테두리의 반사광은 분석이 끝날 때까지 계속 회전한다.

중앙 숫자는 서버가 제공하는 실시간 측정값이 아닌 **시각적 진행률**이다. 실제 요청이 대기 중이면 100% 미만을 유지한다. 서버가 성공 응답을 준 뒤에도 최소 4초 표시를 충족하고 마지막 진행을 마쳐야 100%가 된다. 실패·취소는 완료로 표시하지 않는다. 기존 취소, 스크롤 잠금 해제, 비회원 인증 안내, 실제 보고서로 이어지는 `outline: 'document'` 입자 전환을 유지한다. 비회원에게 실제 점수나 보고서를 먼저 노출하지 않는다.

`/motion-preview?v=8`은 같은 그리기 함수를 사용하는 독립적인 합성 미리보기로 계속 남긴다. v9의 페이지 단계 정책과 콘텐츠 레이어 변경은 실제 앱에 적용하며, 미리보기의 예술적 장면 순서는 바꾸지 않는다. 이 경로는 API 요청 없이 정해진 22초 타임라인으로 재생하며, 실제 앱은 `report-loading.js`와 `LiveAnalysisClock`의 요청 생명주기로 완료 시점을 결정한다. 미리보기 선택은 실제 서비스 설정을 바꾸지 않는다.

## 검토 시안 기록

2026-10-09 윤곽 단순화와 로딩 표시(v8): 가속 시점부터 기존 방사형 눈처럼 위 윤곽은 왼쪽→오른쪽, 아래 윤곽은 오른쪽→왼쪽으로 0.9초 동안 그린다. v7의 섬유 도착 후 네 방향 윤곽 생성 방식은 이번 요청으로 대체했다. 양옆의 원본 유리 이미지·겹선·반짝임을 제거하고 주 윤곽 한 줄, 연한 보조선 한 줄과 거의 투명한 푸른 면으로 정리했다. 원본 이미지에서는 불규칙한 홍채 섬유만 유지한다. 동공 중앙에 0–100% 시연용 진행률을 표시하며, 독립된 링 몸체가 홍채에 녹아든 뒤에도 동일한 R60·8px 띠 안의 반사광은 계속 회전한다. 홍채는 18초에 완성되고 92%로 표시되며, 남은 시연 대기 구간을 지나 22초에 100%와 정지 상태가 된다. 실제 서버 진행률과 연결되지 않은 미리보기다. 이전 구현은 대화 작업 폴더 `work/fixed-anchor-study-before-v8.js`와 `work/motion-preview-before-v8.js`에 보관했다.

2026-10-09 반복 패턴 제거(v6): 사용자가 거울 대칭·꽃잎 형태의 섬유를 다시 명시적으로 거부했다. 초기에 나타나는 8가닥과 강조 가닥을 일정 간격으로 배치하지 않고 시드별 불규칙 위치에서 선택한다. 공통 주기 굴곡과 같은 출발 각도로 돌아오는 곡선 공식을 제거했다. 각 섬유의 제어점 위치·곡률·끝 각도·굵기를 독립적으로 결정하며, 안쪽에서 바깥쪽으로 성장하는 게이지와 고정 동공·스크롤 기준은 유지한다. 최종 홍채는 기존의 미세한 가지 질감을 사용한다.

2026-10-09 스크롤·섬유 성장 수정(v5): `/motion-preview`의 모션 캔버스와 하단 재생/결과 확인 제어를 브라우저 뷰포트에 고정했다. 설명과 스토리보드는 아래에서 스크롤되며, 결과 확인과 장면 선택은 현재 스크롤 위치를 바꾸지 않는다. 같은 캔버스에서 링과 눈을 그리므로 페이지 스크롤에 의한 중심·반지름 차이가 없다.

v5 당시 적용 범위는 검토용 미리보기였다. 제목에 붙은 `journey-motion`과 이동·확대 handoff를 교체하는 실제 앱 연결은 이후 v8 승인으로 완료했다. 현재 연결 방식은 위의 ‘현재 실제 웹페이지’를 따른다.

2026-10-09 링 후속 수정(v4): 원은 동공 구멍 R60 바깥의 일정한 8px 사파이어 띠와 얇은 동심원 반사광으로 표현한다. 둘레별 굵기 변화는 없고 반사광만 회전한다. 결과 확인 시 0.85초 동안 초당 3.5회전까지 부드럽게 가속한다. 눈이 나타나면서 별도의 링은 13.35–15.15초에 완전히 사라지고, 홍채는 18초까지 영역별로 선명해지며 완성된다. 완성 후 별도 회전 링이나 점광원은 남지 않는다. `?v=4&stage=orbit`에서 링부터 재생할 수 있다. 기존 v3 렌더러는 대화 작업 폴더 `work/fixed-anchor-study-before-v4.js`에 복사했다.

2026-10-09 질감 수정: 사용자가 꽃잎처럼 반복되는 곡선 묶음을 거부하고 참고 이미지의 세밀한 홍채·자연스러운 눈꺼풀을 요청했다. 현재 시안은 `public/motion-assets/sapphire-eye-v3.png`의 고해상도 질감을 직접 사용한다. 원본 동공의 중심과 반지름을 장면의 고정 동공에 보정하고, 눈 윤곽 등장·홍채 영역별 드러남·빛의 이동을 코드로 재생한다. 이전 꽃잎 렌더러는 사용하지 않는다. PNG 저장도 아트워크 로딩을 기다려 실제 재생 화면과 같은 질감으로 출력한다. `?stage=analysis`로 완성된 눈부터 확인할 수 있다.

`/motion-preview`는 수정 방향을 확인하는 독립 시안이다. 기존 실제 앱의 분석 API와 연결되지 않는다. `fixed-anchor-study.js`와 같은 그리기 함수로 재생 화면과 8개 장면 이미지를 만든다.

1. ‘지원의 시작은, 내 이력서부터.’ 문장 아래에서 푸른 점이 점등한다.
2. 빛이 오른쪽으로 나아가며 부드러운 곡선을 그린다.
3. 보고서 항목 중 선택한 5개 요소로 선이 갈라진다. 요소 구성은 다시 선택할 수 있다.
4. 요소가 회전하며 최종 동공 위치에 원을 그린다.
5. 완성된 원은 같은 위치와 크기로 계속 회전한다.
6. 결과 확인 시 위치·반지름은 그대로 유지하고 회전만 가속한다.
7. 같은 동공 위치에서 눈 윤곽이 이어 그려지고, 회전하던 링은 홍채에 녹아들며 완전히 사라진다.
8. 물결 면 없이 촘촘한 곡선 섬유가 여러 겹의 방사형 홍채를 이룬다.

시안의 1200×620 기준 화면에서 중심은 `(600,245)`, 동공 반지름은 `60`이다. 원 형성부터 분석까지 이 값은 고정된다. 창 크기가 바뀔 때 장면 전체가 같은 비율로 반응한다. 기준선 토글로 정렬을 확인하며, 타임라인·장면 선택·PNG 저장을 지원한다. 실제 앱은 같은 장면을 `liveMotionViewport()`의 화면 좌표로 변환한다.

## 첫 번째 구현 기록 (방향 철회)

1. 소개와 이력서 미첨부 상태에는 푸른 점이 빛난다.
2. 이력서를 업로드하거나 본문을 저장하는 동안 파동이 생긴다. 서버가 저장을 확인하면 12개 평가 항목을 나타내는 가지와 요소가 펼쳐지고 회전하며 원으로 모인다.
3. 희망 직무·채용공고 화면에서도 원이 계속 회전한다. 화면을 다시 그려도 진행 형태와 회전 각도를 이어받는다. 업로드 실패 시 실제 저장 상태로 돌아간다.
4. 모의지원 분석을 시작하면 현재 형태를 이어받아 원이 눈의 중심으로 이동하며 가속한다. 원이 아직 완성되지 않았다면 먼저 남은 형태 변화를 마친다.
5. 원이 동공 크기로 줄어 동기화된 뒤 눈 윤곽이 그려진다. 안쪽 동공 경계에서 바깥 홍채 경계까지 푸른 면이 퍼진다. 중앙 동공은 비워 둔다.
6. 물결의 바깥 경계는 하나의 연속된 곡선이다. 12개 항목에 대응하는 각도별 진행값과 잔물결에 따라 부분마다 높이가 다르다. 항목 패널의 게이지와 연결점은 같은 경계값을 사용한다.

분석 요청은 시각 전환과 동시에 진행한다. 최소 4초 표시와 실제 서버 성공을 모두 기다리는 기존 조건, 취소, 실패 처리, 비회원 결과 열람 인증을 유지한다. 현재 API에는 12개 항목의 실시간 분석 진행값이 없으므로 물결 높이와 패널 게이지는 **시각적 진행값**이다. 실제 평가 점수로 해석하지 않는다.

## 이전 렌더러 보존과 복원 범위

이전 `matching-eye` 렌더러의 게이지 선택은 `src/shared/design/selected-theme.js`에 남겨 두었다.

```js
export const analysisEyeGauge = 'radial';
```

현재 설정은 이미 `'radial'`이다. 물결 구현, `analysis-renderer.ts`, `analysis-fibres.ts`와 기존 SVG 대체 렌더링은 비교실·기존 렌더러용으로 보존한다. 실제 v8 분석은 `live-eye-motion.js`를 사용하므로 이 값만 바꿔도 실제 앱이 이전 렌더러로 돌아가는 것은 아니다. 이전 동작이 필요하면 해당 렌더러와 `report-loading.js`의 연결 변경을 함께 비교·복원해야 한다.

작업 전 전체 Git 추적 파일은 커밋 `11a184167c6aafac7daf192ed036b5032fd59a4d`에 있으며, 별도 ZIP도 사용자 작업 폴더의 `outputs/CareerLens-frontend-before-liquid-eye-20261008.zip`에 보관했다. 이후 변경을 덮어쓰지 않도록 전체 복원은 별도 폴더에서 비교한 뒤 필요한 파일만 되돌린다.

## 편집 위치와 확인

- `src/features/analysis/journey-motion.js`, `src/shared/styles/journey-motion.css`: 실제 페이지의 점·곡선·5개 요소·고정 회전 원.
- `src/features/analysis/journey-layout.js`: 실제 화면에 맞춘 가지·요소 배치.
- `src/features/analysis/live-eye-motion.js`: 공통 뷰포트 좌표, 실제 분석 중 진행률과 지속 회전, 성공 시 완료.
- `src/features/analysis/fixed-anchor-study.js`, `study-fibre-growth.js`: 실제 앱과 미리보기가 공유하는 v8 링·윤곽·불규칙한 섬유 렌더링.
- `src/app/main.js`: 현재 경로와 업로드 상태에 맞춘 단계 연결, 홈·소개·완료 결과의 과정 모션 제외.
- `src/features/analysis/report-loading.js`, `src/shared/styles/report-transition.css`: 원을 유지한 순백색 페이드 전환, 분석 눈 연결, 기존 분석 생명주기.
- `tools/matching-eye/src/analysis-liquid.ts`, `analysis-liquid-renderer.ts`, `analysis-component.ts`: 보존된 이전 렌더러와 비교실용 게이지·패널·접근성 처리.

v8 JavaScript 모듈 변경에는 `matching-eye` 번들 재빌드가 필요 없다. 보존된 TypeScript 렌더러를 변경할 때는 `tools/matching-eye`에서 `npm run build`를 실행해 `src/features/analysis/matching-eye.js`도 갱신한다. Node.js 단위 검증은 저장소 루트에서 `node --test tests/unit/*.test.mjs`로 실행한다. 실제 앱 연결 검증에는 데스크톱·모바일 스크롤 전후 및 분석 모달 진입 전후의 중심·반지름, 빠른 완료·긴 대기·취소·실패·비회원 인증 흐름을 포함한다. 이력서와 보고서를 변경하는 검증은 합성 데이터와 가상 API 응답으로 진행한다.

프론트엔드 서버의 `/motion-preview`에서 최신 8장면 수정 시안을 재생한다. 실제 이력서, API 요청, 점수를 사용하지 않는다. 미리보기 조작은 실제 서비스의 설정을 변경하지 않는다. 서버 라우트가 추가되기 전에 실행한 서버에서는 재시작 후 사용할 수 있다.

모바일에서는 같은 좌표 함수로 크기와 위치를 조정한다. 모션 줄이기 설정에서는 반복 회전을 생략한다. 페이지 이탈 시 캔버스·이벤트·타이머·애니메이션을 해제하며 숨겨진 탭에서는 반복 재생을 멈춘다.
