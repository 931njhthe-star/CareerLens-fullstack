# 프로젝트 2 화면 정보 구조

2026-10-13 현재 구현 기준. 최신 화면설계서는 docs/design의 새 PowerPoint 파일이다. 화면설계도는 편집 가능한 간략 배치이며 실제 사용자 정보나 분석 결과를 포함하지 않는다.

## 공통 구조

로고는 소개로 이동한다. 주요 메뉴는 이력서·채용공고·모의 지원이며, 과정 화면의 진행표는 이력서 / 채용공고 / 모의 지원의 세 단계다. 희망 직무 선택과 공고 선택은 채용공고 안의 두 내부 단계다.

| 화면 | 주소·진입 | 현재 동작 |
| --- | --- | --- |
| 소개 | #/intro | 약 2.5초 소개, 건너뛰기, 이력서 이동. 분석 과정 배경 모션 없음 |
| 비회원 이력서 | #/resume | UTF-8 Markdown .md, 최대 10MB. 첫 첨부부터 30분 임시 보관. 본문 편집·가상 이력서 패널 없음 |
| 회원 이력서 | #/resume | 파일 선택 즉시 불러오기, 40~50,000자 직접 편집, 가상 이력서 검색·선택, 계정 저장 |
| 희망 직무 | #/desired-role | 목록 선택, 직접 입력 선택 시 직무명 입력. 별도 관심 내용 입력란 없음 |
| 관련 공고 | #/opportunities | 직무 분류·선택 직무·전체 범위, 20개 단위 목록, 상세 내부 스크롤, 결과 확인. 페이지 이동은 열린 상세를 유지 |
| 전체 공고 | #/jobs, #/jobs/:id | 검색·분류·지역 등 필터, 상세, 공고 선택으로 복귀. API가 지원하지 않는 작성·관심 저장은 비활성 |
| 이메일 인증 | #/email, #/signup | 이메일 로그인·가입. 이메일 인증 대기와 인증 완료를 구분. 현재 팀 API의 소셜 로그인·비밀번호 재설정은 미지원 |
| 분석 진행 | 공고의 결과 확인 | 회원은 API·워커, 비회원은 프론트 서버의 실제 엔진으로 계산. 서버 진행률만 표시. 최소 4초 모션과 실제 완료·저장을 모두 확인 |
| 비회원 결과 잠금 | #/result | 계산 완료 결과는 서버에 임시 저장. 빈 피라미드·본문 골격을 흐리고 어둡게 처리하고 인증 팝업 표시. 원문·점수는 인증 전 전달하지 않음 |
| 결과 인증 팝업 | 잠금 화면 위 | 인증된 계정에 기존 결과를 연결. 추가 분석·두 번째 분석 로딩 없이 결과 조회. 3초 이내 표시는 목표이며 성능 보장 아님 |
| 보고서 | #/result, #/reports/:id | 실제 요약·본문·근거·네 축 값. 읽기 숫자만 반올림하고 원본·좌표 유지. null을 0으로 대체하지 않음 |
| 보고서 사이드바 | 보고서 상단 버튼 | 왼쪽 목록·접기, 현재 결과 표시, 서버 순서와 스크롤 유지, 더 불러오기. 좁은 화면에서는 서랍 |
| 마이페이지 | #/mypage | 계정 정보, 보고서 검색·상태 필터·재조회, 지원되는 결과만 개별·선택 삭제. 모든 실제 회원에게 운영 화면 링크 |
| 대시보드 | #/admin | 회원 전용, 관리자 지정 불필요. 최근 실행 표본·상태·성능·선택 실행 상세. 미기록과 0·정상 생략·조회 실패를 구분 |
| 이용 흐름 | /?view=flow | 회원 전용. 전체 이용 기록, 상세 대상 선택, 41개 카드, 로그·시간·세부 기록. 공용 서버 수신·같은 브라우저·가상 시연 모드 구분 |

## 운영 화면 접근과 수집 범위

마이페이지의 두 링크는 같은 탭에서 이동해 기존 탭의 인증을 유지한다. 별도 브라우저에서 직접 열면 그 브라우저에서 로그인해야 한다. 비회원·명시적 시연 계정은 운영 데이터를 조회하지 못한다. 인증 만료를 확인하면 기존 기록을 지우고 로그인 안내로 전환한다.

공용 이용 흐름은 API·워커·비회원 처리와 브라우저의 허용된 상태 메타데이터를 Redis로 공유한다. 원문 문서·보고서·토큰·이메일을 싣지 않는다. 브라우저 관측은 인증된 감사 원장과 다르며 서버 관측과 출처를 구분한다. 다른 사용자의 인증 정보를 공유하지 않는다.

전체 기록은 모든 수신 대상의 최근 200개 이벤트를 표시한다. 지도는 선택한 대상 하나의 41개 카드다. 다른 대상의 이벤트도 전체 기록에는 계속 들어온다. 재연결·숨김 복귀·과거 상태 복원은 새 요청의 빛을 재생하지 않는다. 새 요청과 진행 중 작업이 없으면 카드 색은 중립으로 돌아간다.

## 데이터와 운영 한계

- 회원 보고서는 팀 백엔드에 저장한다. 비회원 계산 후 인증으로 연결한 결과는 프론트 서버의 개인 저장소에 남는다. 백엔드 DB로 자동 이관했다고 표시하지 않는다.
- 현재 프론트 저장 보고서만 삭제를 지원한다. 백엔드가 삭제를 지원하지 않는 보고서는 삭제 버튼을 비활성화한다. 성공 응답을 확인한 항목만 목록에서 제거한다.
- 공용 관찰에는 프론트·백엔드 최신 코드와 같은 Redis를 사용하는 API·워커·프론트가 필요하다. Redis 없는 개발 모드는 프로세스 내부 관찰로 표시한다.
- 이벤트 보관은 24시간·전체 50,000개, 관찰 대상 5,000개다. Redis 장애 중 서버 이벤트는 유실될 수 있으며 완전한 감사 기록을 보장하지 않는다.
- 비회원 처리는 프론트 한 인스턴스·한 프로세스와 영구 볼륨을 전제로 한다. 기본 계산 동시 2건·대기 4건이다. 서버 재시작 중 미완료 계산은 다시 실행해야 한다.
- 실제 배포·모델 분석·인증 메일·운영 부하는 별도 검증 대상이다. [배포 문서](../../infra/deploy/production.md)와 [검증 기록](operations-verification-2026-10-13.md)을 함께 확인한다.
