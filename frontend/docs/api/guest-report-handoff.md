# 비회원 실제 분석 → 로그인 후 결과 공개

2026-10-12 최신 요청: 백엔드 소스를 수정하지 않고 프론트 서버가 실제 분석을 완료한다. 결과를 임시 보관하고 로그인·회원가입 인증 후 현재 보고서 페이지에 바로 적용한다. 로그인 후 재분석하지 않는다.

## 실행과 보관

- `guest_analysis_engine.py`는 형제 폴더 `CareerLens-backend`의 파싱, 평가 그래프, 검증, 12항목 점수 계산, Markdown 렌더러를 그대로 import한다. 해당 Python 의존성과 서버 모델 설정이 필요하다. 모델 키는 브라우저에 전달하지 않는다.
- 근거 임베딩과 검색은 동일 모델·청크·코사인 top-5를 사용하지만 게스트 작업의 메모리 안에서 처리한다. 회원 DB, worker queue, Storage, LangGraph 영구 체크포인트에는 쓰지 않는다. 기업 재무자료가 없는 경우 보고서에 자료 미제공을 명시한다.
- 공고는 프론트 서버가 제공하는 기존 가상 공고 카탈로그를 ID로 확인한다. 브라우저가 보낸 공고 본문·점수·완성 보고서는 신뢰하지 않는다.
- `guest_analysis_service.py`가 진행률과 결과를 `.runtime/guest-reports.sqlite3`에 보관한다. 이 경로는 웹에 노출하지 않으며 Git에서 제외한다. 게스트는 첨부 후 최대 30분, 서버가 정한 더 짧은 만료시간이 있으면 그 시간을 따른다. 만료 즉시 조회·claim이 차단되며 실행 중인 서버는 주기적으로 청소한다.
- 완료 전 응답은 진행 정보뿐이다. 최종 결과 저장까지 성공한 뒤에만 `completed: true`가 된다. CSS 흐림 효과를 접근 제한으로 사용하지 않는다.
- 최초 상태 조회에서 HttpOnly·SameSite cookie를 발급한다. 생성 중복 키, cookie별 실행 제한, 전체 동시 실행 2개와 대기 4개, 문서 길이, 시간 제한을 적용한다. 생성 응답을 받기 전 취소도 요청 키로 중지시킨다.

## API 계약

모든 경로는 `/api/v1/local-guest` 아래에 있다.

| 요청 | 동작 |
|---|---|
| `GET /capabilities` | 실제 엔진 사용 가능 여부·저장소 종류·만료시간, 임시 cookie |
| `POST /analyses` | `{resume_text, job_id, expires_at}`와 `Idempotency-Key`로 실제 계산 시작 |
| `GET /analyses/{id}` | cookie에 연결된 실행의 진행률·완료 여부만 조회 |
| `POST /analyses/{id}/cancel` | 해당 임시 실행 취소 |
| `POST /analyses/cancel-pending` | `{idempotency_key}`로 생성 응답 유실·지연 상태도 취소 |
| `DELETE /analyses/{id}` | 미귀속 임시 자료 파기 |
| `POST /analyses/{id}/claim` | 실제 회원 토큰을 기존 백엔드 `/me`로 검증하고 결과 소유권 확정 |
| `GET /reports` | 검증된 회원 자신의 프론트 서버 저장 보고서 목록 |
| `GET /reports/{id}` / `DELETE /reports/{id}` | 해당 회원 보고서 조회·삭제 |

claim은 같은 회원의 재시도에 같은 결과를 반환하며 다른 회원으로의 재귀속은 거절한다. 원자적 계정 연결이 끝난 뒤에만 보고서 본문·점수·입력 스냅샷·검증된 `owner_user_id`가 반환된다. 이 신원으로 작업을 연결하므로 브라우저가 claim 앞에서 `/me`를 중복 호출하지 않는다. 클라이언트 목록 ID에는 `local-guest:` 접두사를 사용하여 기존 백엔드 평가 ID와 구분한다.

## 화면 흐름

비회원 입력 → 기존 눈 모션과 실제 서버 진행률 → 실제 분석 완료·결과 저장 → 흐리고 어두운 빈 보고서 배경·빈 피라미드·인증 팝업 → 인증 완료 → 이미 계산된 결과 표시. 2026-10-12 추가 요청에 따라 인증 뒤에는 눈 모션이나 별도 로딩 화면을 다시 띄우지 않고 결과를 직접 렌더링한다. 고정 대기나 재분석 요청이 없다. 인증이 완료된 뒤 3초 내 표시가 목표이며 실제 인증 서비스·네트워크 지연까지 보장하는 수치는 아니다.

작업 도중 새로고침하면 동일 실행 상태를 조회한다. 취소, 입력 변경, 계정 전환, 만료 뒤 늦게 도착한 응답은 현재 작업을 덮어쓰지 않는다. 이메일 확인이 필요한 회원가입은 실제 인증이 끝날 때까지 결과 잠금을 유지한다.

## 저장 책임과 운영 범위

인증 후 보고서는 프론트 서버의 계정별 저장소에서 유지되며 마이페이지 목록과 보고서 읽기에 통합된다. 기존 백엔드 `analysis_reports`·대시보드·회원 이력서 DB로 옮기지 않는다. 백엔드 팀이 정식 guest/claim 또는 결과 import 계약을 제공하면 이 저장소를 이관할 수 있다.

이 기능은 현재 로컬 단일 Waitress 프로세스와 형제 백엔드 소스가 있는 실행환경에 적용된다. 분석 엔진이나 API가 없는 서버에서는 비회원 분석 연결 오류를 안내하고 시작하지 않는다. 짧은 모션으로 미리보기 보고서를 만든 뒤 인증 후 분석하는 대체 경로는 사용하지 않는다. `CAREERLENS_GUEST_ANALYSIS=0`으로 새 계산만 끌 수 있다. 계정별 보고서 지속 보관에는 `.runtime` 볼륨 보존이 필요하다. 서버 재시작 시 미완료 작업을 자동 재실행하지 않는다.

프론트 Python 서버를 재시작해야 새 API가 적용된다. JavaScript만 새로고침해도 구형 서버에는 비회원 계산 API가 생기지 않는다. 검증은 합성 모델 응답으로 실제 그래프를 실행하며, 실사용자 문서·계정·유료 모델 호출을 자동 테스트에 쓰지 않는다.

## 이용 흐름 계측 (2026-10-12 20:35 KST)

진행 응답의 `flow_events`는 실제 콜백에서 나온 노드·상태·항목 코드·측정 시간만 최대 100개 제공한다. 원문·점수·이메일·토큰·보고서 식별자는 흐름 이벤트에 포함하지 않는다. `analysis_duration_ms`는 대기열을 제외한 엔진 수행부터 결과 저장 준비까지의 시간이다. `guest_store` 완료는 결과 저장 트랜잭션과 함께 기록되며, 엔진 진행률 100%로 저장 성공을 추정하지 않는다.

기존 SQLite에는 필요한 계측 컬럼만 추가하며 이전 보고서 본문은 보존한다. 이전 실행의 빈 계측을 복원하거나 재분석하지 않는다. 인증 폼의 `result_delivery` 측정은 로그인·가입 성공 응답부터 세션 확인, 계정 연결을 거쳐 보고서 DOM을 표시할 때까지다. 새로고침·외부 인증 복귀 등 시작 시점을 측정하지 못한 경로는 미측정이다. 실패·만료·화면 이동은 성공 표시 시간으로 집계하지 않는다. 실제 모델 및 네트워크 환경의 3초 달성은 별도 실측이 필요하다.
