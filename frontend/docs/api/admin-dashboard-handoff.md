# 대시보드 실제 데이터 연동 — 2026-10-12

대시보드는 전체 계정의 평가 실행 기록을 읽는 운영 화면이다. 마이페이지의 개인 저장 보고서 개수와 다르다. 평가 실행·재실행·삭제나 원격 마이그레이션은 이 화면에서 수행하지 않는다.

## 회원 접근과 다른 PC 실행 (2026-10-13)

대시보드와 이용 흐름은 **가입한 모든 회원**이 마이페이지에서 접근한다. 관리자 ID/역할은 요구하지 않는다. 비회원과 시연 계정은 접근할 수 없으며, 데이터 API도 인증을 검증한다.

프론트와 백엔드를 모두 이번 버전으로 갱신하고 실행 중인 서버를 재시작한다. 예전 공개 접근 패치는 폐기되었다. 익명 요청은 401이어야 하며, 일반 회원의 인증 헤더를 보낸 요청은 DB가 정상일 때 200이어야 한다. 503은 DB·공용 저장소 등의 연결 문제이므로 인증을 제거해서 해결하지 않는다.

여러 기기의 실시간 관찰은 같은 Redis에 연결한 API·워커 및 배포 프론트가 필요하다. 운영 구성은 [전체 배포 안내](../../infra/deploy/production.md)를 따른다. 개인 이력서·보고서 소유권은 유지하고 운영 화면에는 허용된 측정 메타데이터만 제공한다.

## 조회 계약과 갱신

- 요약: `GET /admin/evaluation-performance?days=30&run_limit=100`.
- 선택 실행: `GET /admin/evaluation-performance/{run_id}` → `{ run, generated_at }`.
- 요약 응답의 `scope`는 `accounts: all`, `record_type: evaluation_runs`, `days`, `run_limit`, `sample_count`를 설명한다.
- 최근 30일·최대 100건이 기본이며 서버 조회 한도는 200건이다. 기간·최근 실행 제한을 통과한 실제 표본에 대한 상태와 시간 집계다.
- 여섯 카드는 대기 / 실행 중 / 정상 완료 / 완료·확인 필요 / 실패 / 취소를 표시한다. 목록 상태 필터는 카드 집계에 영향을 주지 않는다. 새로운 미지 상태는 별도로 안내한다.
- 마지막 조회 시각(KST), 요청 한도, 응답 표본 수, 목록 필터 결과를 함께 표시한다. 개인 보고서 개수나 전체 서비스 누적 건수로 표현하지 않는다.
- 브라우저 캐시를 우회하고 60초마다, 화면 복귀 시 새로 조회한다. 숨긴 화면·페이지 이탈에서는 요청을 정리한다. 선택한 실행은 ID로 유지하고 선택 변경·닫기 후 늦게 도착한 응답을 반영하지 않는다.
- 요청 실패는 이전 내용으로 성공을 가장하지 않으며 제어된 한국어 오류와 재시도를 제공한다. 삭제된 실행 상세의 404는 목록을 갱신한다.

2026-10-13 정책에 따라 위 두 GET 모두 회원 인증이 필요하며 관리자 역할은 확인하지 않는다. 개인 이력서·보고서 조회 API의 인증과 소유권은 유지한다. 운영 API를 관리자 여부 판별에 사용하지 않는다. 구형 서버의 401/403에는 로그인·버전 확인 안내를 제공한다.

## 정보 구조

상단 요약 → 높이가 제한된 실행 목록 → 선택한 실행 상세 → 전체 표본의 단계별 시간 순서다. 목록 안에서만 스크롤하며 헤더를 유지한다. 선택 상세의 점수·검증·보고서 정보를 아래에 중복 출력하지 않는다.

상세에는 입력·재현 / 단계·노드·도구·기억 / 검증·재시도 / 점수·보고서 저장 / LLM 사용량·요청 해시 / 시험 증거가 있다. 접기·펼치기와 표 영역은 키보드로 조작할 수 있고 조회 갱신 시 펼침·스크롤 상태를 보존한다. 메타데이터는 기본 2열, 작은 화면에서는 1열이다. 숫자 제목과 값은 모두 오른쪽 정렬한다.

빈 값의 의미를 구분한다.

- **해당 없음:** 문서 전체 파싱처럼 평가 기준 코드가 적용되지 않는 단계.
- **기록 없음:** 저장·제공된 기록이 없음. 기능을 실행하지 않았다는 의미로 추정하지 않는다.
- **조회 실패:** 해당 영역을 읽지 못함. 실제로 데이터가 없다고 표시하지 않는다.
- **미측정:** 시간·비용 계측값 없음. 토큰으로 비용을 임의 계산하지 않는다.
- **계정 열람 미검사:** 실제 인증 계정으로 보고서를 열어보는 검사를 실행하지 않음.
- **점수 없음:** 과거 보류 점수 등 유효한 값 없음. 숫자 0과 구분한다.

## 선택 실행의 공개 메타데이터

`run.availability[section]`의 `status`는 `available`, `partial`, `not_recorded`, `unavailable`이며 `reason`은 서버가 정한 안전한 안내다. 일부 기록만 받은 경우 완전한 합계로 오인하지 않게 안내한다.

| 영역 | 제공되는 값과 의미 |
| --- | --- |
| 입력 | 이력서·공고 식별자, 저장된 서버 입력 형식, 입력 구성 해시와 각 본문 해시 |
| 재현 | 실행 당시 모델·프롬프트·점수·워크플로 버전, 산출물 기록 형식 버전, 출처 설명 |
| 단계·노드 | 실제 상태·시도 번호·소요 시간. 문서 전체 단계의 기준은 해당 없음 |
| 도구 | 실제 저장된 도구 감사 기록 또는 검색 이벤트의 이름·결과 수·시간. 단계명으로 호출을 만들어내지 않음 |
| 기억 | 검색 반환 개수, 그래프 스레드 ID, 체크포인트 수·최신 ID·시각. 검색 반환 합계는 중복 제거 문서 수가 아님 |
| 검증 | 저장된 검증 상태, 평가 기준 재평가 횟수, 전역 이슈와 개별 기준의 확인 필요 상태 |
| 점수 | 저장된 영역·기준별 원점수, 반올림 표시, 판정, 근거 개수. 원문 인용은 공개하지 않음 |
| LLM | 기록된 호출 수·모델·토큰, 호출별 성공·시간·해시. 비용은 실제 기록이 없으면 미측정 |
| 보고서 | 저장 행·본문 존재, 저장 시각, 점수·판정의 현재 형식 호환성. 로그인 계정의 실제 열람과는 별개 |

## 버전과 해시의 출처

- 프롬프트 버전은 실행 생성 시 `evaluation_runs.prompt_version`에 저장한 값이다. 현재 생성 함수의 명시값은 `career-lens-v1`이다. 대시보드가 최신 환경 설정으로 과거 버전을 바꾸지 않는다.
- `reproduction.schema_versions`는 산출물에 저장된 **기록 형식·평가 버전**이다. 평가 산출물의 `scoring.VERSION`과 도구 기록의 `tool-call-v1`이 포함될 수 있다. 이를 실제 JSON 출력 스키마의 버전 번호로 단정하지 않는다.
- 호출의 `schema`는 `CriterionResult` 같은 출력 자료형 이름이다. 호출별 `schema_sha256`은 실제 JSON 출력 스키마를 키 정렬·공백 없는 JSON으로 직렬화한 해시다.
- 입력 구성 해시는 이력서·공고 ID, 각각의 본문 해시, 루브릭, 점수 버전, 모델을 묶은 구성의 SHA-256이다. 한 파일의 해시가 아니다.
- 요청 해시는 각 LLM 호출의 `instruction + NUL + payload`를 UTF-8로 인코딩한 SHA-256이다. 여러 호출의 요청 해시를 하나로 임의 합치지 않는다.
- `prompt_sha256`은 해당 호출의 시스템 지시문 해시다. 새 계측 이전 기록에는 지시문·JSON 스키마 해시가 없으므로 과거 값을 사후 생성하지 않는다.

도움말에는 서버가 제공하는 `version_sources`를 표시한다. 버전 문자열, 입력 구성 해시, 요청 해시, 지시문 해시, JSON 스키마 해시를 서로 바꿔 표시하지 않는다.

## 검증·저장 해석

`partial`은 처리 종료 상태이며 진행률이 아니다. 전역 `validation_issues`의 미해결 수와 `criterion_results.validation_status`는 다른 기록이므로 전역 이슈 0건이 전체 검증 통과를 뜻하지 않는다. 재평가는 통신 재시도와 구분한다.

보고서 본문이 DB에 있어도 과거 `null` 점수·구형 판정 값이 현재 결과 API 형식에 맞지 않을 수 있다. 형식 검사는 저장된 점수·판정 범위만 확인한다. `retrievable`을 DB 존재만으로 true로 만들지 않으며 개인 API에 대신 로그인하지 않는다.

## 공개 범위와 검증

이력서·공고 원문, 근거 인용, 보고서 본문, 프롬프트 본문, 원시 에러·SQL·스택·환경 설정·체크포인트 내용은 공개하지 않는다. 문자열은 HTML 이스케이프하며 사용자 식별 정보나 원문을 일반 JSON 뷰어로 노출하지 않는다.

프론트 단위 검증은 카드의 표본 범위, 0/null 보존, 한국어 상태, 실제 시도 번호, 헤더 정렬, 데이터 없음/실패/로딩 구분, 해시 구분, 공개 원문 억제, 상세 중복 방지, 선택·닫기·늦은 응답, 자동 갱신·캐시 우회, 401/403을 포함한다. 이 테스트 자체는 유료 평가를 실행하지 않는다.
