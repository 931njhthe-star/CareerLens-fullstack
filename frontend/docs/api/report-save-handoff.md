# 저장 보고서 조회 연동

완료 보고서는 기존 백엔드가 자동 저장한다. 프론트는 로그인 계정의 평가 목록과 저장된 본문을 조회해 마이페이지와 과거 보고서 열람을 제공한다. 백엔드 코드·DB·저장 방식은 변경하지 않았다. 수동 저장·북마크·삭제 API는 현재 없으며, 삭제 UI는 연동 대기 상태다.

## 화면 동작

- 로그인한 사용자는 헤더의 `마이페이지`에서 `#/mypage`로 이동한다. 계정의 이름·이메일은 제공된 값만 표시하고, 이력서로 이동할 수 있다.
- 결과 화면의 기존 비활성 `저장하기` 버튼은 `자동 저장됨` 상태 문구로 바뀌었다. `저장한 보고서 불러오기` 링크는 마이페이지의 저장 보고서 목록을 연다. 시연 결과는 `시연 보고서`로 구분한다.
- 목록은 저장 보고서에서 확인한 회사·직무, 날짜·시간(KST), 한글 상태, 짧은 평가 ID와 `보고서 보기` 링크를 표시한다. 회사·직무를 읽는 동안은 `대상 공고 확인 중`, 원문에 정보가 없으면 `대상 공고 정보 없음`을 표시한다. 조회 실패 시 공고 정보만 다시 불러올 수 있다.
- 검색과 상태 필터는 현재 불러온 기록에만 적용한다. `현재 목록 전체 선택`은 필터된 행만 선택하며, 다른 필터에서 선택한 기록이 남아 있으면 현재 목록 밖 선택 수를 안내한다. 개별·선택 삭제 버튼은 실제 백엔드 삭제 API가 없어 비활성화한다. 선택만으로 DB나 브라우저 목록에서 기록을 제거하지 않는다.
- `#/reports/{run_id}`는 해당 평가의 저장 보고서를 연다. URL의 ID는 보고서 ID가 아닌 **평가 ID**이며 인코딩해 전달한다.
- 현재 분석 결과가 있으면 마이페이지에 `현재 분석 결과로 돌아가기` 링크가 표시된다. 저장 보고서 열람과 목록 복귀는 현재 작업의 이력서·선택 공고·편집 내용·분석 결과를 덮어쓰지 않는다.

## 기존 백엔드와 프론트 어댑터

기준 백엔드는 `57bd0cf866b3c66a853f7c79d7cdace5faffefcf` (`develop`)이다. 평가 완료 시 `analysis_reports`에 보고서가 생성되며, 기존 조회 API가 로그인 계정과 소유권을 확인한다.

다음 `/account/reports` 경로는 `src/shared/api/backend-adapter.js`가 처리하는 **프론트 내부 계약**이다. 같은 이름의 백엔드 endpoint를 추가한 것이 아니다.

| 프론트 내부 조회 | 실제 백엔드 요청 |
| --- | --- |
| `GET /account/reports?offset=0` | `GET /evaluations?limit=20&offset=0` |
| `GET /account/reports/{run_id}/context` | `GET /evaluations/{run_id}/result` → `GET /reports/{report_id}` |
| `GET /account/reports/{run_id}` | `GET /evaluations/{run_id}` → `GET /evaluations/{run_id}/result` → `GET /reports/{report_id}` |

목록 응답은 `{ items: [{ id, status, created_at }], next_offset }`이다. 어댑터는 `completed`·`partial` 평가만 `items`에 포함한다. 백엔드에서 받은 평가가 20개이면 `next_offset`은 현재 offset + 20, 그보다 적으면 `null`이다. 다음 위치는 필터링 전 평가 개수로 결정하므로 한 구간에 완료 보고서가 없어도 다음 기록 확인과 `더 불러오기`를 제공한다.

현재 목록 API에는 회사·직무가 없어 각 항목의 평가 결과와 보고서 본문을 추가 조회한다. 최대 3항목의 조회 작업을 동시에 실행한다. 보고서 상단에 명시된 `채용공고:`·`기업:` 항목에서 `{ title, company, source: 'report' }`를 추출한다. 이는 평가 당시 저장된 Markdown의 정보다. 누락된 과거 정보는 현재 브라우저 선택이나 비슷한 공고로 추정하지 않는다.

상세 조회는 평가가 `completed`·`partial`인지 확인한 뒤, 결과의 `reports` 중 가장 최근의 `completed` 보고서를 선택한다. 유효한 완료 보고서나 본문이 없으면 오류를 표시한다. 현재 워크스페이스를 합치거나 저장하지 않고 독립적인 열람용 `draft`를 반환하며, 회사·직무도 해당 보고서에서만 읽는다.

## 결과 표시

`partial`은 **분석 완료 · 일부 확인 필요**다. 분석은 끝났지만 종합점수가 제공되지 않거나 일부 항목에 검증 참고사항이 있다는 뜻이다. 추가 분석을 기다리는 상태나 지원자 전체 평가의 실패로 해석하지 않으며, 없는 점수를 0점으로 바꾸지 않는다.

알려진 상태값은 요약·상태 필드·표에서 한글로 표시한다. 예상 면접 질문·다음 대화 질문 섹션은 화면에서 숨긴다. 이는 표시 단계의 처리이며 API 상태값과 저장된 Markdown 원문은 변경하지 않는다. 일반 문장·링크·코드를 임의로 번역하지 않는다.

## 인증과 조회 상태

마이페이지와 과거 보고서는 로그인해야 열 수 있다. 이 경로를 열기 위해 로그인할 때는 비회원 임시 작업 claim·이력서 업로드를 건너뛰고 요청한 계정 화면으로 돌아간다. 실제 조회는 기존 인증 토큰과 백엔드 소유권 검사를 사용한다.

목록에는 초기 로딩, 빈 상태, 오류·재시도, 추가 로딩 상태가 있다. 더 불러오거나 재시도하는 동안 기존 행을 유지하고 중복 요청 버튼을 비활성화한다. 권한이 없거나 찾을 수 없는 상세 보고서는 조회 불가 안내와 재시도를 제공한다. 화면 이동·로그아웃·계정 변경으로 이전 요청이 끝나도 다른 계정 화면에 결과를 표시하지 않으며, 세션 만료 시 기존 계정 내용을 먼저 비운다.

시연 계정의 목록은 `{ items: [], next_offset: null, demo: true }`로 반환하고 실제 저장 보고서가 없는 시연 상태를 안내한다. 서버 저장을 가장하기 위해 localStorage에 보고서를 복사하거나 다운로드를 실행하지 않는다.

## 검증 범위

렌더링·어댑터·라우팅 테스트는 계정 값 이스케이프, 저장 원문 기반 공고 정보, KST·상태 표시, 필터·선택·삭제 비활성, 페이지 조회·오류·인증 격리와 현재 작업 보존을 확인한다. 합성 입력·가짜 API 기반 검증이며 실제 DB·모델 호출을 의미하지 않는다.

## 백엔드 계약 제안 — 미구현

아래는 추가 합의가 필요한 제안이며 현재 사용 가능한 API가 아니다.

- **구조화된 목록:** 평가 ID·보고서 ID·생성 시각·상태와 평가 당시의 `job_snapshot: { title, company }`, 다음 페이지 위치를 함께 반환한다. 이렇게 해야 목록 표시만을 위해 모든 보고서 본문을 다시 읽지 않아도 된다. 과거 정보가 없으면 명시적으로 비워 둔다.
- **단건·일괄 삭제:** 삭제 대상이 평가인지 보고서인지, 연결된 결과·파일의 처리 범위, 보관 정책을 먼저 확정한다. 서버가 매 요청에서 소유권·삭제 권한을 확인하고 항목별 성공·실패, 이미 삭제된 대상, 부분 실패와 재시도 규칙을 제공해야 한다. 임의의 다른 계정 ID를 삭제할 수 없어야 한다.
- **기능 권한:** 서버에서 검증된 삭제 가능 여부와 오류 계약을 제공한다. 프론트는 계약 연결 후 실제 성공 응답을 받은 항목만 목록에서 제거하며, 실패한 항목은 유지한다. 현재는 삭제 요청 자체를 보내지 않는다.

변경은 로컬 작업본에 유지하며 GitHub 업로드는 별도 요청이 있을 때만 진행한다.
