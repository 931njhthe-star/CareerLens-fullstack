# 희망 직무 분석 흐름 검증 — 2026-10-07

## 최초 분석 흐름 검증 기록

아래는 눈 모션 개선 전의 흐름 검증 기록이다. 개선된 모션의 브라우저 검증과는 구분한다.

- 별도 SQLite 검증 계정과 가상 이력서로 이력서 저장 → 희망 직무 선택 → 분석 화면 → 모의지원 질문 → 최종 보고서를 확인했다.
- 검증 서버에만 요청 지연을 넣어 실행 중 상태를 관찰했다. 실제 API 호출에는 검증용 지연을 추가하지 않았다.
- 각 단계의 서버 완료 응답에 따라 0/3 → 3/3 완료가 표시되고, 전체 완료 뒤 질문 화면으로 자동 이동했다.
- 직무와 관심 분야가 질문에 반영되고, 회사·공고 본문 없이 최종 보고서가 생성되었다.
- 보고서에 눈 그래픽이 없고 준비도 레이더 1개가 표시된다. 결과 프레임의 `overflow-y: auto`를 확인했다.
- 데스크톱에서 꺾인 연결선과 패널을, 좁은 화면에서 세로 배치된 패널을 확인했다. 브라우저 화면 너비보다 문서 폭이 커지지 않았다.
- JS 테스트 45개, 프록시 테스트 9개, 백엔드 테스트 134개 통과. API 계약 1.4.1 동기화 확인.
- 오류·재시도·오래된 응답 무시·입력 변경·세 단계 완료 불변식은 자동 테스트로 확인했다. 모션 감소·WebGL 대체 경로는 코드와 상태 테스트로 확인했으며 실제 저사양 기기 전체를 검증한 것은 아니다.

공개 배포나 GitHub push는 수행하지 않았다. 개인 `.env`와 기존 실행 데이터는 검증에 사용하지 않았다.

## 3초 모션 버전의 이전 자동 검증 — 2026-10-07

`node --test tests/unit/preparation-transition.test.mjs`의 14개 테스트가 통과했다. 이 숫자는 전환 테스트 파일의 결과이며 전체 테스트 합계가 아니다.

- 빠른 분석 완료 시 화면 시작부터 3초가 될 때까지 남은 시간만 기다린다.
- 분석이 3초보다 오래 걸리면 새로운 3초 대기 없이 눈의 종료 모션만 기다린다.
- 최소 표시 시간과 눈 종료 모션은 동시에 기다리며, 둘 중 하나만 끝나서는 다음 화면으로 이동하지 않는다.
- 눈 종료 모션의 Promise가 끝나지 않아도 화면 이탈 시 이동 대기가 취소된다. 취소 후 늦게 도착한 그래픽 오류도 처리한다.
- 동기·비동기 그래픽 실패는 이미 성공한 분석을 오류로 바꾸지 않으며 남은 최소 표시 시간 후 이동한다.
- 시작 전 취소, 실제 짧은 타이머 완료, 실제 대기 타이머 취소와 취소 사유 보존, 최소 표시 시간 중 화면 이탈을 확인했다.

최종 보고서 오버레이로 위치를 옮기기 전 전체 프론트엔드 단위 테스트는 66개가 통과했다. 눈 상태·타이밍 검증은 미완료 분석의 100% 방지, 빠른/느린 완료의 연속적인 진행, 실패 후 이어서 진행, 숨겨진 구간에서 패널 주제·위치 변경을 포함한다. 당시 TypeScript 검사와 Vite 번들 빌드도 통과했다.

## 눈 모션 개선의 이전 브라우저 검증

아래 기록은 질문 준비 단계에 눈이 있던 버전의 결과다. 최종 보고서 오버레이로 옮긴 현재 흐름을 검증했다는 의미는 아니다.

- 별도 검증 계정의 저장된 이력서·희망 직무로 분석 화면을 거쳐 모의지원 질문 화면에 도착했다. 질문 화면에 등장 애니메이션이 적용되는 것을 확인했다.
- 격리된 가상 상태 화면에서 동공이 배경색으로 비어 있고 황금색 홍채가 채워지며, 시작 시 눈의 윤곽선이 따로 그려지는 것을 확인했다.
- 패널이 왼쪽 위/아래, 오른쪽 아래/위에서 내용과 위치를 바꾸어 나타나는 것을 확인했다. 완료 시 수평 접힘 상태를 관찰했다.
- 앱 내 브라우저의 빠른 완료 시나리오는 3,525ms(3초 표시 + 약 520ms 접힘), 가상 8초 분석은 8,847ms에 완료했다. 느린 분석 뒤 별도의 3초 대기가 추가되지 않았다.
- 같은 앱 내 브라우저에서 빠른 완료의 206프레임, 프레임 간격 95백분위 약 17ms를 관찰했다. 이는 이 PC의 해당 실행 결과이며 모든 기기의 성능을 보장하는 수치는 아니다. 가려진 Chrome 창의 프레임 제한은 별도로 관찰했다.
- 390px 화면에서 문서 폭도 390px이며 눈 아래에 패널 하나가 표시되었다. 작은 홍채에서 나타난 선의 간섭 무늬는 화면 크기에 맞는 선 개수와 미분 기반 안티앨리어싱으로 수정하고 한 차례 재확인했다.
- 모션 감소 및 WebGL 대체 경로는 코드·자동 테스트로 점검했으며 실제 OS 설정 변경이나 모든 GPU에서의 시각 검증까지 수행한 것은 아니다.

검증 화면과 가상 상태는 무시되는 `.runtime`에만 두었다. 개인 `.env`와 실제 사용자 데이터는 변경하지 않았으며 공개 배포나 GitHub push는 수행하지 않았다.

## 최종 보고서 오버레이의 현재 흐름과 자동 검증

현재 흐름은 이력서 → 희망 직무 → 텍스트로 질문 준비 → 모의지원 답변 → 최종 보고서 오버레이 → 결과 보고서다. 질문 준비 단계에는 눈 모션과 최소 대기가 없다. 답변 제출 후 배경을 220ms 동안 어둡게 만든 뒤 눈의 바깥 윤곽과 동공 윤곽을 함께 그린다. 홍채의 가느다란 황금색 방사형 선은 `/analysis` 요청과 동시에 최소 4초 동안 각각 차오르며, 유효한 최종 보고서 응답 이후에만 전체 완료할 수 있다. 개별 선의 게이지는 시각적 연출이며 각각의 실제 서버 작업 완료율이 아니다. 눈이 520ms 동안 접히고 배경이 160ms 동안 사라진 뒤 결과를 연다. 느린 API 응답 뒤 새로운 4초 대기를 추가하지 않는다.

`tests/unit/report-loading.test.mjs`의 42개 테스트가 통과했다. 다음 항목을 확인했다.

- 기존 질문 준비나 이전 보고서가 완료되어 있어도 최종 보고서 로딩은 미완료 상태로 시작한다.
- 제출한 답변을 `/analysis`에 보내고, 유효한 결과 수신 후에만 워크스페이스를 갱신한다.
- 비정상 보고서 객체·점수·목록 형식은 완료 처리하지 않는다. 결과 화면이 사용하는 `questions` 목록도 검사한다.
- 분석 API 실패 시 답변과 저장된 입력을 유지하고, 워크스페이스 갱신만 실패한 경우 유효한 생성 결과를 보존한다.
- 갱신 중 발생한 인증·권한·입력 충돌 오류는 성공으로 숨기지 않는다.
- 요청 전 취소, 분석 응답 또는 오류의 늦은 도착, 갱신 중 취소에서 결과 적용을 막는다.

4초·방사형 선 개편 전 전체 프론트엔드 단위 테스트는 108개 모두 통과했다. 이전 사전 분석 화면에 눈이 있다고 기대하던 화면 구조 테스트는 텍스트 상태와 재시도를 확인하도록 갱신했다.

## 방사형 선 개편 전 오버레이의 브라우저 검증

- 데스크톱에서 질문을 제출하면 URL은 `#/questions`를 유지하며 기존 입력 화면 위에 전체 화면 모달이 열렸다. 모달의 눈 주변 바탕은 투명하고, 검정 74%의 배경 어둡게 처리가 먼저 나타난 뒤 눈 외곽과 동공 윤곽의 그리기가 함께 시작되는 것을 확인했다.
- 실제 분석 API 응답 이후 눈이 접히고, `#/result`로 이동하면서 결과 본문에 `prepared-page-enter`가 적용되는 것을 확인했다.
- 너비 390px 화면에서 문서의 스크롤 폭도 390px이었다. 높이 586px의 모달 내용은 높이 844px 화면 안에 들어왔다.
- `입력으로 돌아가기` 버튼을 누르면 기존 답변 텍스트가 유지되고, 모달이 제거되며 `body.style.overflow`가 원래 빈 값으로 돌아왔다.
- 검증용 503 응답에서는 답변 텍스트가 보존되고 제출 버튼이 다시 활성화되었으며 결과 화면으로 자동 이동하지 않았다.
- 어두워진 흰 페이지 위에서 외곽선과 동공 테두리가 흐리게 보이던 부분은 오버레이 모드의 선 밝기·굵기를 높여 수정했고, 데스크톱·390px 화면에서 한 차례 최종 확인했다. 모션 감소 설정과 브라우저 뒤로 가기는 이번 브라우저 검증에서 직접 확인하지 않았으며, 코드·자동 테스트 확인과 구분한다.

## 4초·방사형 선 개편의 검증

현재 최소 표시 시간은 눈 타임라인과 그래픽 대체 전환 모두 4,000ms로 맞췄다. 진행 중 곡선의 시간 상수는 1,600ms로 조정해 앞부분에 진행 표시가 몰리지 않고 4초 동안 변화를 읽을 수 있게 했다. API 응답 후에는 기존 240ms의 짧은 마무리 보간과 520ms 폴딩을 유지하며 새로운 4초 대기를 시작하지 않는다.

`node --test tests/unit/analysis-motion.test.mjs tests/unit/preparation-transition.test.mjs`의 24개 테스트가 통과했다. 4,000ms 직전·경계·직후 완료 조건, 느린 응답의 추가 대기 방지, 연속적이고 역행하지 않는 진행, 실패·재시도·취소와 종료 모션 대기를 확인했다. 빠른 최종 응답에 근거 정보가 하나뿐이어도 세 영역의 기본 주제가 유지되고, 미완료 영역의 미검증 근거가 패널에 나오지 않음을 검사했다. 영역별 선·패널 게이지와 전체 평균 백분율은 실제 서버 작업량이 아닌 시각적 진행 값이다.

- 전체 프론트엔드 단위 테스트 117개, TypeScript 검사와 Vite 번들 빌드가 통과했다. 새 바늘 테스트 6개는 선의 결정적 배치, 세 그룹의 분산, 동공 가장자리에서 시작하는 단조 성장, 서로 다른 속도, 실제 완료 전 전체 채움 방지와 그룹별 진행 값을 확인한다.
- 앱 내 브라우저의 격리 화면에서 빠른 완료는 4,530ms(4초 성장 + 약 520ms 접힘), 266프레임, 프레임 간격 95백분위 약 17ms였다. 이 PC의 해당 실행 측정값이며 다른 기기 성능을 보장하지 않는다.
- 실제 질문 페이지 위 오버레이를 1,280×900과 390×844에서 확인했다. 동공은 비어 있고, 금색 바늘이 여러 방향에서 서로 다른 길이로 자라며 패널의 주제와 위치가 교체된다. 모바일 문서의 가로 넘침은 없었다. 검증용으로 6초 지연한 API 응답 후 결과 페이지 이동도 확인했다.
- WebGL 컨텍스트 손실을 격리 화면에서 발생시켜 SVG 대체 그래픽을 확인했다. 대체 그래픽에서 화면 폭 변경 시 바늘 개수가 고정되던 문제를 수정한 뒤 한 차례 재확인했다. 390px의 120개와 1,280px의 180개가 패널 계산 기준과 함께 바뀐다. 브라우저 오류·경고는 관찰되지 않았다.
- 모션 감소는 코드·자동 테스트 확인 범위이며 이번에 실제 OS 설정을 변경하지 않았다. 위의 3초 버전 브라우저 측정값은 과거 기록이다. 개인 `.env`와 사용자 데이터는 검증에 사용하지 않았으며 공개 배포·GitHub push는 수행하지 않았다.
