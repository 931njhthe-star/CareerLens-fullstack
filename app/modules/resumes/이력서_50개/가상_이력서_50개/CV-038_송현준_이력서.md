## 프로젝트

### 고객 요청 재처리

- 기간·유형: 2026-02 ~ 2026-05 · 업무 팀 프로젝트
- 목적: 요청 키와 재처리 기록을 연결해 재시도에 따른 중복 처리를 방지
- 참여 인원·본인 역할: 4명, 본인은 API·상태·오류 처리 담당. 화면과 입력 자료 구성은 팀원 담당
- 사용 기술: Python, FastAPI, Pydantic, LangGraph, LLM API, Git, pytest, PostgreSQL, Docker
- 주요 구현: 입력 검증 → 조건 분기 → 도구 조회·업무 실행 → 결과 확인 → LLM 응답 → 출력 검사 구성. 요청 키와 재처리 기록을 도구에 연결; 조회 실패 재시도는 최대 2회로 제한. 요청 ID별 실행 상태·오류 로그 저장, 컨테이너 기반 내부 실행 환경 관리
- 문제 해결: 재시도로 같은 업무가 여러 번 처리됨 → 요청 키와 재처리 기록을 도구에 연결
- 성과: 동일한 합성 사례 58건에서 기대 분기와 일치한 사례가 49건에서 55건으로 증가. 불일치 3건을 후속 검토 목록으로 관리

### 고객 요청 재처리 처리 기준 정리

- 기간·유형: 2021-03 ~ 2021-05 · 업무 과제

- 주요 수행: Java 요청 키·재처리 큐 관리. 입력 누락·확인 대기 사례를 별도 항목으로 기록
- 결과: 정상 처리와 확인이 필요한 요청의 구분표 작성, 검토 의견 반영
